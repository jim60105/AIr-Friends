# 頻率限制防護

為了避免惡意使用者透過高頻率標記對機器人發動拒絕服務攻擊（DoS），或導致外部 API 額度瞬間耗盡，AIr-Friends 內建精準的滑動視窗頻率限制器（Rate Limiter）。

---

## 實作架構與演算法

頻率限制邏輯實作於 `src/core/rate-limiter.ts`，採用**每使用者滑動視窗時間戳記佇列（Sliding-Window Timestamp Queue）**並結合冷卻懲罰機制：

1. **滑動時間視窗 (Window)**：系統維護每個使用者的請求時間戳記陣列。當新請求到達時，先剔除視窗時間外的過期時間戳記。
2. **最大請求容量 (Capacity / Burst)**：若剩餘時間戳記數量超過設定的上限值（`maxRequests`），代表觸發頻率限制。
3. **冷卻懲罰期 (Cooldown Period)**：一旦使用者被判定超標，該使用者會被標記進入冷卻狀態（`cooldownUntil`）。在冷卻期結束前，任何新發送的請求皆會被直接拒絕，且不計入佇列中。

---

## 組態參數設定

在 `config.yaml` 中配置 `rateLimit` 區塊：

```yaml
rateLimit:
  enabled: true          # 是否啟用頻率限制 (預設: true)
  windowMs: 60000        # 滑動視窗時間 (毫秒)，預設 60 秒 (60000)
  maxRequests: 5         # 單一視窗內允許的最大請求次數 (預設: 5)
  cooldownMs: 30000      # 觸發超標後的強制冷卻時間 (毫秒)，預設 30 秒 (30000)
```

---

## 防護行為與使用者回饋

- **靜默丟棄或友善通知**：當一般使用者超標時，系統可設定發送「請求過於頻繁，請稍候重試」的提示訊息，或是靜默丟棄該請求以避免通知訊息本身造成二度刷屏。
- **管理員豁免**：針對系統白名單帳號或特定高權限角色，可在組態中設定略過頻率限制器評估。
- **自動記憶體回收**：長時間未活動的使用者記錄會在背景定期由記憶體回收機制清理，避免記憶體無止盡增長。
