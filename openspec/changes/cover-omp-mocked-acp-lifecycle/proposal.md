# Proposal: cover-omp-mocked-acp-lifecycle

## Why

Rows 6/10/11/13/14a/14b/15/20 each shipped per-component unit/mock suites that verify their own decision logic in isolation, but design §14's "Mock ACP subprocess/connection fixtures may exercise new/prompt/cancel/load, crashes, and registry updates" acceptance and §16's P9a row require a COMBINED deterministic mock-ACP lifecycle suite driving the REAL `AgentConnector` + `AgentProcessPool` + `SessionOrchestrator` wiring across modes, ownership, and readiness. That cross-component surface is structurally invisible to the per-row unit suites: a crash-reconnect that restores row 6's config cache INSIDE row 10's mode-keyed pool entry behind row 13's readiness gate never executes in any single row's unit file. P9a closes exactly that gap — test coverage only, no behavior change.

## What Changes

- **New combined integration suite** (deterministic, mock-only) under `tests/integration/` driving the real connector/pool/orchestrator classes with mock ACP subprocess/connection fixtures (extending the existing `tests/mocks/mock-acp-agent.ts` stdio-JSON-RPC pattern and extracting the connector-test inline mock-connection pattern into a shared `tests/mocks/mock-acp-connection.ts`), covering ONLY cross-component scenarios — every scenario requires at least two landed rows' components interacting:
  - **Lifecycle happy path:** initialize/new/prompt/cancel/load end-to-end through real pool acquisition (row 10 mode resolution + mode-composed key), real readiness gate consumption (row 13), and real config-options cache population (row 6) in one flow.
  - **Crash → reconnect → same-mode load:** mock subprocess crash mid-prompt; real recovery re-enters the SAME mode's pool entry (row 10) with row 11 ownership verification, restores the canonical config-options cache from the `session/load` response and reapplies model/reasoning through row 6's real stable-first logic (grouped catalog, `none`→`off` alias), and re-establishes the recovered session's OWN gate context (row 11/row 4) — model reapplication asserted through real code, not a mocked callback.
  - **Cross-mode ownership rejection both directions:** restricted recovery context loading a native-YOLO-owned session and vice versa (row 10's recorded ownership fields + row 11's verify-before-teardown), asserting violation, no opposite-mode process/lease touch, and sibling isolation in the combined stack.
  - **Gate-context restoration correct-session after crash:** after reconnect, a re-issued prompt's filesystem/permission decisions come from the recovered session's own gate context, never a sibling's (row 11 restore + row 4 sink authorization evaluated for real inside the same flow).
  - **Deny-until-ready composition:** first-prompt gate (row 13) denying a restricted session whose readiness is unresolved at the shipped fail-closed `ReadinessChannel` seam, through the real orchestrator path — and the post-start operator-MCP-refresh path where the registry-epoch bump resets readiness (row 13) and the 14b wiring re-admits provenance on the fresh epoch through 14a's REAL decision modules (live-provenance, inventory, MCP admission), with the combined ordering (refresh → epoch bump → readiness reset → re-observe → re-admit/deny) asserted as one flow.
  - **Dual-mode lease serialization:** a restricted and a native-YOLO session coexisting in one channel (row 10's two pool entries/processes) still serialize on the single global execution lease (row 10 pool + orchestrator) — asserted behaviorally through acquisitions, not construction.
  - **Restricted LSP posture across lifecycle transitions:** a restricted crash-respawn and a same-mode load preserve the row-15 `--no-lsp` + overlay pin launch posture (row 15 + rows 9/11/8 launch/recovery composition), while the YOLO session's launch gains none of it (D6).
  - **OpenCode-only regression flows:** OpenCode initialize/new/prompt/cancel/load and pool reuse through the same harness with pool keys, spawn environment, and command strings byte-compared against the current shipped values where meaningful (row 10's byte-identity contract + row 13's OpenCode exemption + row 15's untouched `yolo` agent), with zero readiness/extension involvement.
- **Fail-closed honest posture asserted, never mocked green:** every unresolved inherited seam — readiness control channel (`ReadinessChannel` unimplemented → `NotReady` → deny), MCP admission basis (`needs-mechanism-audit`), record reset (INCOMPATIBLE, surviving lower-layer records never grant), destructive-intent decoding (UNRESOLVED → shared fail-closed verdict) — is exercised to its DENY/blocked outcome in these combined tests. Synthetic-positive fixtures (a labeled established-readiness tuple, a labeled trusted-provenance tool) are the ONLY allow paths, each labeled per the P0 fixture rule, and NO test asserts or implies the native OMP binary invokes, honors, or enforces anything (design §15 boundary).
- **Non-duplication rule with justified deletions:** no scenario restates a single-component unit assertion already shipped by rows 1–20's suites; a redundancy audit at implementation time MAY delete a unit case ONLY when this suite fully supersedes it, each deletion individually justified in the commit body. No existing unit suite is otherwise modified.
- **Shared helper extraction:** `tests/mocks/omp-mock-session.ts` — the shared OMP mock session builder (mode/ownership/config-options/readiness/epoch fixture assembly) built here and consumed unchanged by row 22's skill-handoff regression; `tests/mocks/mock-acp-connection.ts` — the scripted in-process ACP connection extracted from the existing inline connector-test pattern; `tests/mocks/mock-acp-agent.ts` extended additively (OMP-shaped config-option catalogs, scripted crash-trigger and registry-refresh RPCs) without changing existing OpenCode mock behavior.
- **Determinism contract:** no sleeps or wall-clock races — subprocess interactions await explicit JSON-RPC messages, timer-driven paths (idle timeout, readiness timeouts, reclaim) use the existing `@std/testing` `FakeTime` pattern, crashes are triggered by an explicit scripted RPC rather than delay-based kill races. No network, no paid credentials, no real agents, no `omp --version`, no container/bwrap: the suite lives in `deno test:integration` and must not silently invoke live acceptance; coverage stays above the existing >75% gates.
- **Docs note:** a `tests/README.md` test-map (unit vs integration vs mock acceptance, determinism rules, the P0 fixture-labeling rule, the §15 evidence boundary) — the docs note this change owes; final README/AGENTS/changelog consistency remains row 22's.
- **Explicit non-goals (named):** per-spawn/pool payload → Skill API → mock-platform reply regression (row 22 `finish-omp-mocked-skill-handoff`); final docs/changelog/OpenSpec sync (row 22); ANY production behavior change — implementation touches `tests/` only; if implementation discovers a genuinely untestable seam (candidate: a test-only command/executable override hook on the OMP launch path if row 9's factory does not already expose one to the integration harness), it ships at most that minimal, reported seam addition and NOTHING else; P0 verdict revisions; dashboard restart-flow coverage; container/build smoke (all §15 user-owned).

## Capabilities

### New Capabilities

None. The acceptance obligations extend the existing `acp-integration` capability rather than fork a test-only specification.

### Modified Capabilities

- `acp-integration`: Add requirements for the combined deterministic mock-ACP lifecycle acceptance suite — the cross-component scenario matrix (lifecycle happy path, crash→same-mode-load with config restoration, cross-mode ownership rejection both directions, correct-session gate-context restoration, deny-until-ready with post-start refresh re-admission epoch composition, dual-mode lease serialization, restricted LSP posture across lifecycle transitions, OpenCode byte-compare regression), the fail-closed honest-posture and P0 fixture-labeling rules applied to this suite, the non-duplication/justified-deletion rule, the shared mock-session/connection helper contract consumed by row 22, and the determinism/no-live-acceptance execution contract. All predecessor rows' behavior requirements are referenced, never modified.

## Impact

Eventual implementation owns ONLY test-tree files: `tests/integration/omp-lifecycle/` (the combined suites), `tests/mocks/mock-acp-connection.ts` (new shared scripted connection), `tests/mocks/mock-acp-agent.ts` (additive OMP-shaped scripting), `tests/mocks/omp-mock-session.ts` (new shared OMP session builder, row-22 contract), `tests/README.md` (test-map note), and the deletion-only cleanup of unit cases this suite fully supersedes (justified per case). `deno.json` is untouched — the suite runs under the existing `test:integration` task. NO production file is edited; the single pre-declared exception is a test-only launch-command override seam on the OMP factory path IF AND ONLY IF the row-9 factory offers none to the integration harness — flagged to the parent in the implementation return, never silently expanded. `CHANGELOG.md` is explicitly OMITTED here (test-only, no consumer-visible behavior; the changelog sync for the whole OMP batch is row 22's committed obligation) — `config.example.yaml`, `.env.example`, `helm/values.yaml` untouched, zero new fields.

Evidence posture inherited, restated without softening: this suite proves the INTEGRATION CODE composes the shipped decisions correctly on fixtures. Because the mock ACP process does not run the trusted extension, the registry-refresh/provenance scenario composes the real 14b handler module and 14a decision modules with the real connector-side epoch/readiness state through simulated tool-metadata observation — that composition is client/extension-module evidence only; real extension load, real handler invocation, real cross-mode native load rejection, and real readiness emission stay on the design §15 user checklist. No passing result here clears any inherited unresolved gate.
