# Proposal: cover-omp-mocked-acp-lifecycle

## Why

Rows 6/10/11/14a/14b/P5d/20 have per-component decision tests. This combined deterministic mock-ACP suite drives real connector/pool/orchestrator composition across lifecycle, ownership, configuration, handler availability and live registry freshness. Row 13 is removed; there is no readiness handshake or channel seam. No readiness handshake or readiness-channel seam is required. If the extension handler is not installed, the pinned non-YOLO native approval mode plus the client ACP policy remain the boundary for ACP-mediated operations; restricted sessions still fail closed on client policy denials. This does not provide the missing restricted capability set or an equivalent native default-deny boundary. `runner.emit` only logs lifecycle-hook errors and does not fail session startup, so extension-load failure remains an accepted residual risk with no client-observable readiness assertion.

## What Changes

- **New combined integration suite** (deterministic, mock-only) under `tests/integration/` driving the real connector/pool/orchestrator classes with mock ACP subprocess/connection fixtures (extending the existing `tests/mocks/mock-acp-agent.ts` stdio-JSON-RPC pattern and extracting the connector-test inline mock-connection pattern into a shared `tests/mocks/mock-acp-connection.ts`), covering ONLY cross-component scenarios — every scenario requires at least two landed rows' components interacting:
  - **Lifecycle happy path:** initialize/new/prompt/cancel/load through real mode-scoped pool acquisition, ACP client policy and canonical config-options population, with no readiness handshake.
  - **Crash → reconnect → same-mode load:** mock subprocess crash mid-prompt; real recovery re-enters the SAME mode's pool entry (row 10) with row 11 ownership verification, restores the canonical config-options cache from the `session/load` response and reapplies model/reasoning through row 6's real stable-first logic (grouped catalog, `none`→`off` alias), and re-establishes the recovered session's OWN gate context (row 11/row 4) — model reapplication asserted through real code, not a mocked callback.
  - **Cross-mode ownership rejection both directions:** restricted recovery context loading a native-YOLO-owned session and vice versa (row 10's recorded ownership fields + row 11's verify-before-teardown), asserting violation, no opposite-mode process/lease touch, and sibling isolation in the combined stack.
  - **Gate-context restoration correct-session after crash:** after reconnect, a re-issued prompt's filesystem/permission decisions come from the recovered session's own gate context, never a sibling's (row 11 restore + row 4 sink authorization evaluated for real inside the same flow).
  - **No-handshake boundary composition:** absent extension handler retains pinned non-YOLO native approval posture plus ACP-mediated client policy; an unauthorized ACP request fails closed with no side effect, without a synthetic ready tuple or first-prompt readiness rejection. Installed-handler fixtures separately compose real 14b/14a decisions; refresh → registryEpoch bump → live re-observation → admission/denial uses resourceGeneration freshness, never readiness reset.
  - **Dual-mode lease serialization:** a restricted and a native-YOLO session coexisting in one channel (row 10's two pool entries/processes) still serialize on the single global execution lease (row 10 pool + orchestrator) — asserted behaviorally through acquisitions, not construction.
  - **Both-mode LSP posture across lifecycle:** restricted and native-YOLO respawn/load preserve their selected LSP disable carriers. OpenCode build+yolo per-agent explicit denies are compared to config as landed after numbered rows 15 and 17; implicit-startup suppression remains unverified.
  - **OpenCode regression:** initialize/new/prompt/cancel/load and pool reuse with commands/env/keys compared to the shipped post-row-17 baseline. Both agents retain explicit lsp denial; no OMP extension or readiness interaction.
- **Honest fail-closed posture:** no readiness seam exists. Assert client-policy denials with no handler and installed-handler provenance/incomplete-destructive/record-survival denials; preserve MCP audit-needed and inherited verdicts independently from DECIDED dispositions. Synthetic tool observations are labeled, without inventing readiness or claiming native installation/enforcement. No readiness handshake or readiness-channel seam is required. If the extension handler is not installed, the pinned non-YOLO native approval mode plus the client ACP policy remain the boundary for ACP-mediated operations; restricted sessions still fail closed on client policy denials. This does not provide the missing restricted capability set or an equivalent native default-deny boundary. `runner.emit` only logs lifecycle-hook errors and does not fail session startup, so extension-load failure remains an accepted residual risk with no client-observable readiness assertion.
- **Non-duplication rule with justified deletions:** no scenario restates a single-component unit assertion already shipped by rows 1–20's suites; a redundancy audit at implementation time MAY delete a unit case ONLY when this suite fully supersedes it, each deletion individually justified in the commit body. No existing unit suite is otherwise modified.
- **Shared helper extraction:** `tests/mocks/omp-mock-session.ts` — the shared OMP mock session builder (mode/ownership/config-options/handler-availability/epoch fixture assembly) built here and consumed unchanged by row 22's skill-handoff regression; `tests/mocks/mock-acp-connection.ts` — the scripted in-process ACP connection extracted from the existing inline connector-test pattern; `tests/mocks/mock-acp-agent.ts` extended additively (OMP-shaped config-option catalogs, scripted crash-trigger and registry-refresh RPCs) without changing existing OpenCode mock behavior.
- **Determinism contract:** no sleeps or wall-clock races — subprocess interactions await explicit JSON-RPC messages, timer-driven paths (idle timeout and reclaim) use the existing `@std/testing` `FakeTime` pattern, crashes are triggered by an explicit scripted RPC rather than delay-based kill races. No network, no paid credentials, no real agents, no `omp --version`, no container/bwrap: the suite lives in `deno test:integration` and must not silently invoke live acceptance; coverage stays above the existing >75% gates.
- **Docs note:** a `tests/README.md` test-map (unit vs integration vs mock acceptance, determinism rules, the P0 fixture-labeling rule, the §15 evidence boundary) — the docs note this change owes; final README/AGENTS/changelog consistency remains row 22's.
- **Explicit non-goals (named):** per-spawn/pool payload → Skill API → mock-platform reply regression (row 22 `finish-omp-mocked-skill-handoff`); final docs/changelog/OpenSpec sync (row 22); ANY production behavior change — implementation touches `tests/` only; if implementation discovers a genuinely untestable seam (candidate: a test-only command/executable override hook on the OMP launch path if row 9's factory does not already expose one to the integration harness), it ships at most that minimal, reported seam addition and NOTHING else; P0 verdict revisions; dashboard restart-flow coverage; container/build smoke (all §15 user-owned).

## Capabilities

### New Capabilities

None. The acceptance obligations extend the existing `acp-integration` capability rather than fork a test-only specification.

### Modified Capabilities

- `acp-integration`: Add requirements for the combined deterministic mock-ACP lifecycle acceptance suite — the cross-component scenario matrix (lifecycle happy path, crash→same-mode-load with config restoration, cross-mode ownership rejection both directions, correct-session gate-context restoration, no-handshake fallback and post-start refresh re-admission epoch composition, dual-mode lease serialization, both-mode LSP posture across lifecycle transitions, OpenCode byte-compare regression), the fail-closed honest-posture and P0 fixture-labeling rules applied to this suite, the non-duplication/justified-deletion rule, the shared mock-session/connection helper contract consumed by row 22, and the determinism/no-live-acceptance execution contract. All predecessor rows' behavior requirements are referenced, never modified.

## Impact

Eventual implementation owns ONLY test-tree files: `tests/integration/omp-lifecycle/` (the combined suites), `tests/mocks/mock-acp-connection.ts` (new shared scripted connection), `tests/mocks/mock-acp-agent.ts` (additive OMP-shaped scripting), `tests/mocks/omp-mock-session.ts` (new shared OMP session builder, row-22 contract), `tests/README.md` (test-map note), and the deletion-only cleanup of unit cases this suite fully supersedes (justified per case). `deno.json` is untouched — the suite runs under the existing `test:integration` task. NO production file is edited; the single pre-declared exception is a test-only launch-command override seam on the OMP factory path IF AND ONLY IF the row-9 factory offers none to the integration harness — flagged to the parent in the implementation return, never silently expanded. `CHANGELOG.md` is explicitly OMITTED here (test-only, no consumer-visible behavior; the changelog sync for the whole OMP batch is row 22's committed obligation) — `config.example.yaml`, `.env.example`, `helm/values.yaml` untouched, zero new fields.

The mock process does not load the trusted extension. Registry-refresh composition uses real 14b/14a modules on synthetic live metadata and wiring-owned registryEpoch/resourceGeneration, proving decisions only. Absent-handler ACP denial demonstrates client policy only, never native callback coverage or equivalent default-deny. Real extension load/invocation, cross-mode native rejection and all-mode implicit LSP suppression remain user-owned/unverified; no readiness emission is requested.
