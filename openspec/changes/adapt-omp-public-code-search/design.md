## Goals / Non-Goals

**Goals:** An honest, citation-frozen answer to "what does OpenCode provide today for public code/docs search, and what does pinned OMP offer as an equivalent" (verdict: the parity tool was removed upstream; no supported OMP equivalent exists under the approved credential set); a pure adapter-contract module + route table that complete this row the moment a supported backend/credential decision lands, delegating every hop to row 17's core; a spec-locked interface-parity contract (excerpts, attribution, repo/path metadata, documented size bounds, row-18 error rules verbatim); an additive, credential-gated 14a seam marker that keeps the fail-closed `userDecisionRequired` gap in the current state; deterministic mock-only certification; unrestricted-egress posture preserved; NEVER_PASS secrets never promoted.

**Non-Goals:** No generic web search (row 18, landed), no local grep/glob/find work (native, 14a-allowed, unchanged), no LSP (D5), no new credential/env/config field (`GITHUB_TOKEN`/`GH_TOKEN` stay NEVER_PASS; no `GREP_APP_API_TOKEN` invented — it does not exist), no re-pointing of git-backup secrets, no `github` tool admission or non-search operation (14a denies it), no keyless scraping tool, no trusted-extension sibling in the current no-supported-credential state (the slot is reserved by contract, unconsumed), no MCP facade, no packaging (row 20), no OpenCode behavior change, no YOLO clamp (D6), no live network/paid calls, no modification of `ssrf.ts`, `egress-proxy.ts`, `fetch-transport.ts`, `fetch-routes.ts`, `search-transport.ts`, `search-routes.ts`, 14a's tables, or 14b's composition.

## Decisions

### D1. The parity baseline is frozen at the pins, and it says "removed"

C1–C3 are implementation data in `code-search-routes.ts`. The design refuses to preserve a capability OpenCode itself deleted at 2026-05-12: the parity requirement of design §6/D4 is satisfied by (a) local text search staying native (14a allow row), (b) public code/docs **content** reachable through rows 17/18's completed routes (URL reads — including the code/docs-hosting special handlers of C8 as validated secondary hops — and provider-grounded web search), and (c) this change's adapter contract + honest gap for a dedicated public-code-**search** backend. The batch contract's grep_app/gh_grep premise (C4/C5) is recorded as false at the pins rather than assumed; no artifact invents a skill or token that the audit cannot cite.

### D2. Credential gate is a decision input, and NEVER_PASS is never softened

The GitHub Code Search API adapter sketch (the route a future provisioning would complete) consumes exactly the credential mechanism the deployment may already have: a GitHub token already present in the operator's environment is *not a new field*, and row 18's rule applies — "do not require an unrelated vendor secret merely to select OMP." But at these pins the same token's registered purpose is git backup/credential-store (C4), 14a puts it in `NEVER_PASS_ENV`, and using it as a code-search credential is a **new consumer role** expanding a repo-write-capable secret into the restricted agent process. D2 therefore: `decideCodeSearchRoute(input, deps)` takes `credentialPresence` as a pure decision input (which read-only code-search token, delivered through row 7's approved config path, exists for the restricted process — never logged, never in records); with none present the only decision is `blocked_pending_adapter` + `userDecisionRequired` and **zero** network calls; this change never promotes a NEVER_PASS name, and a test asserts no route-table row, fixture, or doc names a promoted secret or requires a credential outside what a future row-7 credential-set revision would deliver.

### D3. Every hop delegates to row 17; no second network stack

`code-search-transport.ts` imports `decideFetchHop`/`planFetchRoute` from `fetch-transport.ts` (import-only, per row 17/18 contracts): search endpoint requests and any result-enrichment subrequest are hops in row 17's loop (public-only classification through the single `ssrf.ts` rule set, enforcing posture → validating proxy via `getRunningEgressProxyUrl()`, operator-`unrestricted` → today's posture with no new denials, `redirect: "manual"` per hop, 5-hop bound, credential-free `{ host, hopIndex, decision, reason }` records). Code-search-only reason additions are credential-scope codes (`no-supported-credential`); no new posture value, no local SSRF copy, no YOLO-only clamp.

### D4. No tool registered now; registerTool is the reserved completion mechanism

Because every backend-specific route tiers `no-supported-mechanism` (GitHub API: credential gate unpassed; native `github search_code`: gh binary + auth store + subprocess transport, C6/C7) or `candidate-to-verify — not selected` (searchcode/Sourcegraph scraping, C8, mirroring row 18's refusal of keyless scraping engines), this change registers **no** trusted-extension tool. The route table's mechanism column names the pinned `registerTool` replacement/addition surface (row 17 S7/S8, consumed verbatim) as what a future completion would use — landing as the 6th serial sibling of the 12→13→14b→17→18 tree — and the module pins the observable contract that sibling must satisfy (input shape, hop delegation, interface D5). This is not a stub of a tool: it is the adapter-contract decision core plus frozen tiering, which is this row's actual content under honest tiering; the tool itself is unreachable work until the user decision lands, and saying so is the batch's own honesty rule.

### D5. Interface parity contract (future-complete, spec-locked)

Whenever a supported backend exists, the result MUST be the native-shaped envelope with: per-item **excerpts** (bounded text-match/code preview — pinned reference bound: preview limit 50 with limit default 10 / max 50, C9), **source attribution** (source URL + provider), **repo/path metadata** (`nameWithOwner`-style repository identity + file path + language, from `apiCodeToSearchResult`/`formatSearchCodeResults`, C9), query echo, and documented total-size bounds. Honesty rules copy row 18 verbatim: auth/rate/HTTP/malformed → honest native-shape tool errors (no fabrication), single controlled attempt per decision (no unguarded retry), no agent switch, zero-results = honest empty distinct from error. Decision records/logs never carry credentials, headers, query strings, or payload bytes.

### D6. Seam completion is conditional and additive; cross-table agreement pins it

14a's public-code-search row gains a `completing-adapter` marker whose *activation* is gated on the route table's supported-credential predicate — structurally the same conditional marker row 18 defined for web search, but in the current state its gate is never satisfied, so the effective decision stays `allow-gated-pending-adapter` and 14b keeps `rejected_pending_adapter`. Row 17's registry is imported, never edited: its public-code-search subrequest rows remain pending until this change's contract is satisfied, and the reused cross-table agreement test (row 18 pattern) asserts neither table claims completion the other denies. 14a's own pending-vs-allow test stays green; no composition-order/error-vocabulary change.

### D7. Test surface is decisions, not plumbing; P0 fixture rule holds

`tests/acp/omp-code-search-transport-decisions.test.ts` (mocked endpoint/DNS): public search-endpoint hosts allowed (enforcing names the proxy route; unrestricted adds no denial); loopback/RFC1918/link-local/ULA/metadata endpoints and synthetic redirect `Location`s blocked with class named and zero issued requests; >5-hop chains block with the hop-limit reason; credential-presence matrix (supported token fixture present / absent) yields the reserved-route decision / `blocked_pending_adapter` + `userDecisionRequired` with NO transport call; NEVER_PASS fixtures prove a `GITHUB_TOKEN`-only environment still blocks (no promotion). `tests/acp/omp-code-search-interface-shape.test.ts`: mocked search responses (matches with excerpts, zero-results, 401, 429, malformed) assert excerpt/attribution/repo-path/limit behavior and the empty-vs-error distinction; records/log scan is credential- and payload-free. Route-table suite: frozen tiering with citations, marker-gate never satisfied now, marker ≠ allow, URL-read rows byte-identical, cross-table agreement. All mocked; the compiled binary's real behavior (including that today's `github` tool is never reachable under 14a's deny) stays section-15 user checklist.

## Risks / Trade-offs

- **The honest verdict could be read as silently cutting D4's parity** → it is the opposite: parity is decomposed into what verifiably exists (local search, URL-read content path, provider-grounded web search) plus an explicit `userDecisionRequired` gap for the deleted dedicated backend, with the gap, both decision options, and the exact provisioning path documented in `docs/OMP_NETWORK.md`; the spec keeps the route pending rather than relabeling.
- **A future registerTool completion could prove unusable in the compiled binary** → identical exposure to rows 17/18: static-read mechanism; section-15 observation owns it; meanwhile the fail-closed block stands, which is the design's escalation, not a silent cut.
- **Interface parity of an unbuilt tool is a contract, not an observation** → every shape element cites the pinned formatters/limits (C9) so the future sibling has a falsifiable target; drift surfaces as a failing shape test at completion time; nothing today claims a running tool.
- **Keyless scraping could look "free" and tempting** → refused by the same rule row 18 applied to scraping engines: arbitrary-provider surface without operator configuration; C8 notes the *existing* fetch-handler path remains available through row 17's controlled transport, so "no scraping tool" ≠ "can't read those public sites."
- **Reserved 6th serial slot vs row 20 digest** → the slot is unconsumed (no sibling lands), which strictly reduces serial conflict; the conflict table records the reservation so row 20 and any completion change order themselves correctly.
- **GITHUB_TOKEN pressure** ("the operator already has one, just use it") → D2's blast-radius analysis is the documented rejection; the user decision can still choose a *separate read-only* credential through row 7's path, which is the only supported shape.

## Migration Plan

Additive: pure modules + route-table data + conditional seam marker land behind the existing restricted launch path with no behavior change in the current state (the route stays blocked exactly as 14b composes it today). Rollback = revert the marker/module import; the route is pending again — never native. No config, state, or data migrations; OpenCode flows untouched.

## Open Questions

None blocking. Whether the user provisions a read-only code-search credential (which flips the reserved registerTool completion into implementation) is a user decision this change deliberately surfaces rather than answers. Whether pinned OMP ever adds a supported code-search provider is a pin-change question handled by the P0-revision + re-audit path 14a already mandates.
