## Context

See `proposal.md`, the approved design sections 5, 8, 11 and 14–15, and all artifacts of dependency `establish-omp-compatibility-contracts`. Existing `src/acp/client.ts` has session-context overrides, private token expansion, lexical `isWithinDir` checks and direct Deno read/write calls. Its structured paths expand session TMPDIR as `{cwd}/tmp`, whereas command environment handling can use process TMPDIR. The helper must not perpetuate that conflation. Existing `src/utils/path-validator.ts` protects other workspace APIs lexically; changing those unrelated APIs is not this change.

P0's known record-reset incompatibility and unresolved discovery/readiness/transport/skill-selection boundaries remain application blockers. Consume its actual verdict and `CriticalSkillContract`; do not redefine its evidence, claim a native `skill://` mapping exists, or treat hypothetical positive fixtures as pinned native support. Drafting these artifacts is allowed while application is blocked.

## Goals / Non-Goals

**Goals:** A complete, operation-neutral library with directly observable context resolution, root identities, canonical existing/new-target decisions and precise errors. It must provide the data needed by both secure access and policy consumers without deciding extension/command rules or granting IO authority.

**Non-Goals:** Actual protected read/write/mkdir/delete/move calls, platform-specific no-follow adapters, client/session registration cutover, destructive parsing, native skill discovery, pool/state allocation, prompt recipes or broader Skill API/workspace hardening. Rows 3/4 own access and sink adoption respectively. No runtime/agent configuration or new deployment fields, no shims or migrations.

## Decisions

### 1. Explicit context in; immutable observations out

Create only `src/acp/filesystem-roots.ts` and its focused unit test. Use repository `@std/path` path conventions and Deno metadata APIs, with a narrow injectable metadata reader (`lstat`, `realPath`) for error/replacement fixtures; no new dependency or generic filesystem abstraction. Proposed AIr helper signatures are not upstream OMP APIs:

- `resolveSessionPath(path, context) -> Result<ResolvedSessionPath>` performs deterministic contextual expansion/normalization without protected IO.
- `canonicalizeSessionRoots(context, trustedSkills?) -> Promise<Result<CanonicalSessionRoots>>` validates and observes applicable roots.
- `resolveFilesystemTarget(resolvedPath, roots, expectation, criticalReference?) -> Promise<Result<CanonicalTarget>>` observes an existing or prospective target and returns matching root roles, not a permission grant. The optional critical reference supplies the predecessor contract's instruction/source identity and resource generation for an explicitly trusted lookup; it is not required for ordinary workspace paths.

`Result<T>` is a discriminated `{ok:true,value:T}` or `{ok:false,reason:RootPathFailure}`. No success value on failure; no empty-string root, lexical fallback or catch-and-allow. Context includes exact ACP session ID, Skill API session ID, absolute cwd, explicit absolute staging path, optional shared Agent workspace, and session context generation. Trusted callers provide these from authoritative session ownership, not model input or process environment. A context missing/mismatching the requesting ACP ID is invalid; there is no daemon/first-session fallback. The library holds no session map and makes no new/load lifecycle decisions; row 4 selects contexts and row 11 restores them.

The canonical staging location remains `{cwd}/tmp/{skillSessionId}` (the existing Skill API payload location). Validate the supplied staging path equals that contextual path after normalization. `$TMPDIR` still means `{cwd}/tmp` for legacy structured paths, not a pool/mode process TMPDIR. Process TMPDIR, `PI_CODING_AGENT_DIR`, state namespace and subprocess `SESSION_ID` are not helper inputs granting roots. Session ID is a literal single path component, never sanitized into a different session identity. Absolute cwd/staging/shared roots are required; invalid/missing session ownership is a named context failure.

### 2. Path syntax and compatibility

Expand exactly `$TMPDIR`, `${TMPDIR}`, `$SESSION_ID`, `${SESSION_ID}`, `$AGENT_WORKSPACE` and `${AGENT_WORKSPACE}` using this context; unbraced forms require a variable-name boundary. An unavailable value referenced by a token is an error, never empty expansion. Unknown variable forms such as `$TMPDIR2`, `$SESSION_ID2`, `$HOME`, `$OTHER` or `${OTHER}` remain unexpanded and yield `unresolved_token`, even when a literal directory with that spelling happens to exist. Do not execute shell syntax, expand `~`, glob, unescape or parse file contents. Reject empty paths, NUL and URI/device references as `invalid_path`; HTTP(S)/`skill://` are routed by their separate consumers and are not filesystem paths here. Bare literal dollar characters that are not variable syntax remain filename data.

Normalize the expanded filesystem path once against session cwd with repository path utilities; absolute paths stay absolute. This normalized absolute value is the helper's target identity and the only path consumers may pass on to access resolution, not the original token-bearing string. Preserve existing token-boundary behavior and absolute OpenCode callers; correct relative-path anchoring to session cwd rather than daemon cwd. Do not expand native schemes or modify bash command parsing. Native/destructive consumers must separately bind the helper target to execution semantics under P0's execution-binding contract; this library cannot authorize a differently interpreted raw path.

### 3. Root identity and missing staging

Root roles are `workspace`, `staging`, `shared`, and `trusted-skills`. Workspace and configured shared/skills roots must exist as directories; optional absent shared/skills roots grant nothing. A configured-but-unresolvable root is a failure, not optional omission. Resolve supplied root aliases canonically, record normalized configured path, canonical path and observed identity (`dev`/`ino` where metadata supplies them), plus session/context generation and root role. A host-provisioned root alias is anchored to its observed canonical identity; request-time child symlinks do not create new roots. Identity fields are observations, not held descriptors or immutable proof. Do not fabricate inode values on platforms without them; row 3 determines which secure-access mechanisms are supported or fails closed there.

Allow a not-yet-created staging directory without creating it: observe its nearest existing directory ancestor and normalized missing component suffix under the canonical workspace, with a `prospective` discriminator. Validate its physical destination equals `{canonical workspace}/tmp/{skillSessionId}`, not merely some subdirectory inside the workspace. This also covers lazily absent `tmp/`. If an existing staging directory resolves to another session's directory, ordinary workspace location or process-state alias rather than its own canonical payload location, reject staging identity. Root construction never calls mkdir. Shared and workspace may coincide for self-research; preserve both roles without ordering them into a broader grant. Workspace may contain staging, but trusted skills must be canonically disjoint from writable workspace/shared roots (neither may contain the other).

### 4. Existing/new-target canonicalization and symlinks

Use equal-or-separator containment, never raw string-prefix checks. Find candidate root roles from the normalized requested path using configured and canonical root spellings. Walk existing components below the candidate root using lstat and canonical observations; inspect final-file as well as parent symlinks. Every observed symlink traversal must remain within that same candidate root, not merely end in some other allowed root. An alias from workspace to shared, sibling workspace, sibling staging or external file cannot launder a root-role grant. A contained symlink is eligible at the observation layer and returns the canonical root-relative destination, original normalized path and symlink evidence; the later secure adapter must safely operate on that destination or reject unsupported traversal, never blindly reopen the raw path.

`expectation` is `existing-file`, `existing-directory`, `existing-any`, or `file-or-new`. Existing targets return canonical target path, root-relative components, actual target type and metadata identity. Final directories are invalid for file expectations; non-file/non-directory special nodes are invalid for all expectations. A missing target fails `not_found` for existing-only expectations. For `file-or-new`, treat a true missing component as prospective only after lstat proves it absent: observe the nearest existing **directory** ancestor, canonicalize it, and append only validated missing filename/directory components. Return ancestor identity, missing components in order and the prospective canonical target. Do not create directories or files. Existing non-directory parents, dangling final/parent symlinks, link loops, escaping links, inaccessible ancestors and non-NotFound metadata errors are failures, not evidence that a new target is safe. If realPath fails NotFound after lstat saw an object, treat the inconsistent observation as `path_changed`, not a new path.

For overlapping workspace/staging roles, return independent physical membership. A link spelled inside staging but physically targeting another place in the workspace may retain broad workspace membership, but can never receive staging membership. If staging root validation itself failed, fail root construction rather than downgrade its identity. The policy consumer uses returned physical roles: restricted narrow staging access and shared grants are row 4's decisions, not a grant derived from a lexical prefix.

### 5. Trusted skills without name-only trust

The optional skills-root input carries deployment-owned provenance and the read-only root/source identity from P0's `CriticalSkillContract`, not an arbitrary agent-supplied directory or HOME-discovered name. Validate canonical root agreement with that contract and disjointness from writable roots. For a critical reference, require the contract's exact canonical instruction path and current resource-generation binding; do not choose a same-name workspace file. The helper may validate this data but cannot establish native selection or refresh support; that remains P0/row 12's responsibility.

`trusted-skills` membership is explicitly read-only in output, even if a consumer is YOLO. A skills link leaving the owned root cannot obtain this role even if its destination is otherwise readable. A workspace file cannot become trusted by naming it `SKILL.md`. Return ownership mismatch, external-link or stale-generation failure for an explicitly trusted reference. Unrelated workspace read-extension rules are unchanged; row 4 implements the trusted-read exception separately from normal workspace extensions. No skills write exception is created.

### 6. Error contract and secure-access handoff

Export finite reasons: `invalid_context`, `invalid_path`, `unresolved_token`, `invalid_root`, `root_unavailable`, `root_overlap`, `outside_roots`, `symlink_escape`, `dangling_symlink`, `symlink_loop`, `not_found`, `wrong_target_type`, `canonicalization_failed`, `path_changed`, `trusted_identity_mismatch`. Deterministically prefer context/syntax errors, then root-construction errors, then target-resolution errors. If no lexical candidate root exists return `outside_roots`; if a candidate's traversal escapes it return `symlink_escape`. Successful role matching may retain an independently valid broad role when a narrower role does not match; do not suppress actual metadata failures. Preserve internal error cause for developers without logging contents/secrets or returning an unbounded raw exception as the decision. Row 4 maps one failure to existing bounded rejection diagnostics.

A `CanonicalTarget` carries session/context generation, root roles and root identities, normalized input, canonical target/root-relative destination, target or ancestor identity, target type/prospective discriminator, missing suffix and observed symlinks. It never contains `authorized:true`, a reusable permission token or a guarantee that metadata will remain stable. All outputs are treated as immutable, operation-scoped observations; a caller cannot use another session/generation's result.

Row 3 must re-establish containment with secure root-relative/no-follow access and handle root/ancestor/final replacement through actual IO. A precheck or second realPath alone is not race-proof. Tests here cover inconsistencies during metadata observation and decisions after replacement, not prevention of the subsequent check/use race; actual operation race tests belong to row 3. No filesystem-access promise depends on optional bwrap. Native YOLO continues broad ACP containment in workspace/shared roots and receives no staging-only, extension, LSP, command or tool denial from this library. State files already inside that broad workspace are not specially denied in YOLO; native non-ACP execution is not covered by these helpers.

### 7. Direct consumer tests and documentation

Use Deno temp directories with `finally` cleanup to exercise actual helper outputs: two session roots, shared root, owned skills root, existing files, missing nested files/parents, internal/external parent and final symlinks, staging-to-sibling and staging-to-ordinary aliases, canonical root aliases, same-prefix siblings and root equality. Assert canonical destination, relative components, role membership, prospective ancestor/suffix and specific failures, not forwarding counts or source strings.

Use metadata mocks only for permission/I/O errors, unsupported identity availability and deterministic replacement between observations. Assert zero protected mutation/read-content calls because the helper exposes metadata only. Cover legacy braced/unbraced tokens, unknown variable-prefix tokens, missing context/identity, absolute/relative input, optional roots, root failures/overlap, missing/dangling/loop errors, file/directory types, generation mismatch and critical skills ownership. Agent-neutral contexts yield the same physical observations for OpenCode/OMP; YOLO broad membership survives sibling-state paths inside the same workspace without a restricted grant. These tests certify helper behavior only, not native ACP delegation, OMP discovery, immutable deployment mounts or race-safe IO.

Update existing `docs/AGENT_PERMISSIONS.md` with this library's contract and row 3/4 handoff/evidence limits, plus `CHANGELOG.md`. No new config/env fields means examples and Helm are intentionally unchanged. Do not describe the running client as hardened before cutover.

## Risks / Trade-offs

- RealPath/lstat can race and inode availability varies. Observations remain advisory to the secure access adapter, not authority to call ordinary path IO.
- Safe contained symlinks require deliberate access support; row 3 may reject unsupported traversal but cannot silently fall back to unsafe path operations.
- Canonical root ownership cannot prove native critical-skill selection or deployment immutability; preserve P0's source blocker and user's unverified runtime checklist.
- Existing callback and general workspace APIs remain unchanged in this slice. This is a complete reusable decision library, not a claim of whole-application security completion.
- Read-only skills disjointness is stricter than a path-name convention, intentionally preventing owned-root trust inside agent-writable paths.
