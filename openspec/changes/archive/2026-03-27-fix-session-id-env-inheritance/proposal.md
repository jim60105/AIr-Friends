## Why

Shell-based skills require `--session-id "$SESSION_ID"` to authenticate with the Skill API Server. The `SESSION_ID` environment variable is in the sandbox allowlist (`BASE_ALLOWED_ENV` in `sandbox-manager.ts`), but it is never explicitly set in the subprocess env dict built by `buildBaseAgentConfig()` in `src/acp/agent-factory.ts`. The `Deno.env.set("SESSION_ID", sessionId)` call in `session-orchestrator.ts` only modifies the parent process environment after the subprocess is already spawned, so the agent subprocess never inherits it.

The `shellSessionId` (our Skill API session ID) is generated by `sessionRegistry.register()` **before** `createAgentConfig()` is called, so it is available at subprocess spawn time. We must pass it through `createAgentConfig()` into the subprocess env dict so that `$SESSION_ID` resolves correctly in the agent's bash subshells.

## What Changes

- Add a `sessionId` parameter to `createAgentConfig()` and `buildBaseAgentConfig()` in `src/acp/agent-factory.ts`
- Set `env["SESSION_ID"] = sessionId` in the env dict for all three agent types (copilot, gemini, opencode), following the same pattern as `AGENT_WORKSPACE` and `TMPDIR`
- In `session-orchestrator.ts`, pass `shellSessionId` to `createAgentConfig()` at all call sites
- Remove the now-unnecessary `Deno.env.set("SESSION_ID", ...)` and `Deno.env.delete("SESSION_ID")` calls

## Capabilities

### Modified Capabilities

- `acp-session-management`: SESSION_ID is reliably propagated to the agent subprocess environment at spawn time so that `$SESSION_ID` resolves correctly in bash subshells when executing skill scripts

## Impact

- `src/acp/agent-factory.ts` — Add `sessionId` parameter; set `env["SESSION_ID"]` in all agent type branches
- `src/core/session-orchestrator.ts` — Pass `shellSessionId` to `createAgentConfig()`; remove `Deno.env.set/delete("SESSION_ID")` calls
- `src/acp/sandbox-manager.ts` — No changes; `SESSION_ID` already in allowlist
- Skills and SKILL.md files — No changes; they already correctly use `$SESSION_ID`
