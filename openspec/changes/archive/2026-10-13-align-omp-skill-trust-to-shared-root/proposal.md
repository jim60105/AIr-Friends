# Proposal

## Why

`unify-skill-root-and-inventory` makes both agent types resolve one shared skill root from one configuration value. OMP then refuses that root at three separate layers. The owned-skill admission ladder requires an absolute canonical path, a link-free every-component walk and a real directory or file, then rejects an agent-writable tree (`mode & 0o222` with a non-root owner), rejects group/world-writable entries and requires `nlink === 1` for files (`src/acp/omp/owned-skills.ts:61-87`). The extension's read replacement repeats the same clauses at the root, the target and every directory component (`src/acp/omp/extension/read-replacement.ts:296-369`). The daemon's ACP canonical-root observation enforces them again on every callback (`src/acp/filesystem-roots.ts:596-614`, `(mode & 0o022) !== 0 || ((mode & 0o200) !== 0 && uid !== 0)`). The `skill://` authorization is wired to the image constant (`src/acp/omp/extension/native-registration.ts:775`) and the extension reads its declared root from the fixed image document (`src/acp/omp/extension/{bootstrap.ts:114-116,critical-skills.ts:31-81}`), while the settings source plan throws unless the declared root is exactly `[OMP_IMAGE_SKILLS_ROOT]` (`src/acp/omp-settings.ts:699-702`, `:995`, with the literal `/opt/air/skills` embedded in both composed mode documents at `:769-770` and `:885-886`). A `uid 1000:0` `775` shared tree — the tree the image already ships at `/home/deno/.agents/skills` — fails all of them, so the shared root is unusable for OMP reads and execution.

## What Changes

- **OMP admits the shared root at every layer.** The ownership clauses are dropped at the root, the target and each ladder component, in the extension and in the daemon's canonical-root observation alike. **BREAKING** (security posture): the OMP skill tree is no longer required to be root-owned, agent-non-writable or group/world-non-writable — an accepted relaxation, recorded once in `design.md` with the compensating invariants that keep the denial behavior intact (canonical absolute path, link-free components, real dir/file, `nlink === 1` for files, realpath containment, supplied device/inode identity, current generation). Critical minting keeps its enforcement point: the producer derives the read-only fact from the observed root instead of asserting it, and a candidate matching a pinned critical identifier's `SKILL.md` layout is refused in a writable tree.
- **The declared root is the resolved root.** `ompSettingsSourcePlan`, `assertOwnedSettingsDocument` and the composed mode documents take the resolved skill root as a parameter instead of asserting the constant, and `src/acp/agent-factory.ts` passes the root it already resolved. The carrier of the declaration becomes explicit: the generated declaration declares exactly that root, and the authored mode documents carry the pins and declare no skill directory.
- **The declaration is generated and cannot out-rank the pins.** Each mode's generated declaration contains exactly one key — the skill custom-directory array holding the resolved root — is written into its own deployment-owned directory with a symlink-refusing, unconditionally-overwriting write, and is passed FIRST among the `--config` overlays so the authored mode document stays last and a rewritten declaration can never loosen another pin.
- **The extension learns the root from its launch environment.** The daemon conveys the resolved root in the deployment-owned spawn environment, verified by the existing environment finalization; the extension reads it, verifies it is one absolute existing non-link directory its own observation accepts, and denies with zero skill authority when it is absent or unacceptable — in both the per-spawn and pooled shapes.
- **The extension and the daemon stop importing the constant**, the authored mode documents stop hard-coding a skill directory, and the digest manifest is recut over every changed `/opt/air/omp` input, overlays and installed extension closure alike.
- **OMP ownership, settings, spawn, discovery, network and acceptance docs restated**, plus the docs and tests that pin the old trust ladder.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `acp-integration`: `Trusted Read-Only ACP Skills Root Identity`, `Read-Only Trusted Skills Access In ACP Callbacks`, `Mode-Separated Owned OMP Settings Content`, `Deployment-Owned OMP Skill Root Settings`, `Owned Skill URIs Remain Readable Through Native Read`, `Owned Replacement Admission Preserves Separate Completion` and `Canonical Critical-Skill Ownership Across New, Load, and Refresh` — the ownership clauses at both the extension and callback layers, the declaration parameterization, carrier and placement, and the pinned root constant. New: the shared-root admission contract for OMP reads and execution (including the extension's launch-environment conveyance), and the denial invariants that survive the relaxation.
