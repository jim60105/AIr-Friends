## Why

Design §9 + D4 require the restricted OMP deployment to keep live web-search capability parity (OpenCode's `agent-config/opencode.json` ships `websearch: "allow"` for `build`), yet the pinned `web_search` tool sends every provider request out on **global fetch** with automatic redirect following and `fetchWithRetry` retries: `executeSearch` (`web/search/index.ts`) builds the provider `SearchParams` literal **without** a `fetch` field, so the `params.fetch?: FetchImpl` seam that both candidate providers honor (`providers/gemini.ts` `(fetchImpl ?? fetch)`, `providers/openrouter.ts` `(params.fetch ?? fetch)`) is never populated on the ACP path — the exact same PARTIAL shape P0/row 17 recorded for the URL-read `ToolSession.fetch`. Under an enforcing egress posture 14a's `allow-gated-pending-adapter` therefore makes 14b fail every `web_search` call closed with `rejected_pending_adapter` and a `userDecisionRequired` marker. Until a search adapter lands, restricted OMP loses live search parity with OpenCode; the fix must not require an unrelated vendor secret (design §9: "do not require an unrelated vendor secret merely to select OMP") and must not invent a mechanism for a backend the pinned source does not back.

## What Changes

- Audit the pinned OMP `v18.6.1` / `2a2c6dcbbb558c0f8145f67f28b3370984f2bf60` web-search surfaces and tier each **supported / candidate-to-verify / no-supported-mechanism** with source citations, keyed to the row-7 credential set (`GEMINI_API_KEY` + `OPENROUTER_API_KEY` ONLY). Frozen audit verdicts at the pin (static source reads, not executed behavior):
  - **SUPPORTED**: Gemini developer-API grounding via `GEMINI_API_KEY` — `GeminiProvider` `google-generative-ai` path calls the provider endpoint with `x-goog-api-key` from `modelRegistry.resolver`; availability is `authStorage.keys.source(model.provider) !== undefined` and the `google` provider's env fallback is `GEMINI_API_KEY` (`providers/gemini.ts`, `@oh-my-pi/pi-ai` `providers/google.ts`).
  - **SUPPORTED**: OpenRouter web-plugin grounding via `OPENROUTER_API_KEY` — `OpenRouterGroundedProvider` POSTs `${model.baseUrl}/chat/completions` with `plugins:[{id:"web"}]`; availability is `authStorage.keys.source(model.provider ?? "openrouter") !== undefined`, whose env fallback is `OPENROUTER_API_KEY` (`providers/openrouter.ts`, catalog env table).
  - **no-supported-mechanism under this credential set** (real in the pinned catalog, but selectable only with a secret the design refuses to add): grounded `anthropic`/`codex`/`xai`/`openai` (`providers/anthropic.ts` `$env.ANTHROPIC_SEARCH_API_KEY`, `providers/openai.ts`, and the codex/xai transports need their own provider credentials or OAuth), and the paid pure `web/<id>` search engines (`brave`→`BRAVE_API_KEY`, `tavily`/`exa`/`jina`/`perplexity`/`kagi`/`firecrawl`/… in `web/search/provider.ts` `PROVIDER_LOADERS`). Requiring any of these would be an unrelated vendor secret (design §9, batch out-of-scope "Additional provider secrets unrelated to supported AIr configuration"); they stay blocked.
  - **candidate-to-verify, NOT selected** (arbitrary-provider surface the batch forbids): the keyless scraping engines in `PROVIDER_LOADERS` (`duckduckgo`, `mojeek`, `ecosia`, `startpage`, `public`, the scraping `google` provider) — they need no secret but are operator-unconfigured scraping backends, so admitting them would add arbitrary-provider config, which this change never does.
- Add the search transport adapter as a pure decision + interface-shape module plus its consumer contract, reusing row 17's mechanism wholesale rather than forking a second network stack: `decideSearchTransport(input, deps)` delegates to row 17's `decideFetchHop`/`planFetchRoute` (`src/acp/omp/fetch-transport.ts`) — the same `ssrf.ts` single classifier, the same `enforcing` (`egressProxy && !unrestrictedEgress`) vs operator-`unrestricted` posture, `getRunningEgressProxyUrl()` routing, `MAX_REDIRECT_HOPS = 5` manual per-hop revalidation, and credential-free `{ host, hopIndex, decision, reason }` records. `src/utils/ssrf.ts`, `src/utils/egress-proxy.ts`, and row 17's `fetch-transport.ts`/`fetch-routes.ts` stay read-only imports.
- Define the search adapter contract that a trusted-extension `web_search` replacement executes: (a) the provider endpoint (Gemini `:streamGenerateContent` developer endpoint / OpenRouter `/chat/completions`) and every result-enrichment subrequest (notably Gemini's `vertexaisearch.cloud.google.com/grounding-api-redirect` HEAD resolutions in `finalizeGeminiSearchResult`/`resolveGroundingRedirect`) are issued **through the controlled transport** — validating proxy under enforcing posture, `redirect: "manual"` per hop, no `fetchWithRetry` unguarded native retry outside the controlled path; (b) the search tool's result/citation/error **interface stays the agent's native shape** — the `formatForLLM` layout (`## Sources`/`## Citations` with `[n] title / url / snippet` attribution), the `details.response = { provider, sources, citations }` details object, the `{content:[{type:"text"}], details}` result envelope, and the honest **empty-result vs error** distinction (`availableProviderCount === 0` error message and the `SearchProviderError` "no sources" 204 case are surfaced, never fabricated). Query interface (`query`, `recency`, `limit`, `max_tokens`, `temperature`, `num_search_results`) is unchanged, preserving OpenCode prompt parity.
- Honesty rules, spec-locked: provider/auth/rate/HTTP errors surface as honest native tool errors (`formatSearchProviderFailure`/`formatSearchProviderFailures` shapes) — **never** fabricated results, **never** an unguarded native transport retry outside the controlled transport, **never** an agent switch on failure. When NO supported backend exists for the restricted process under the existing credential set (both `GEMINI_API_KEY` and `OPENROUTER_API_KEY` absent for the search-relevant providers), the web-search route stays `blocked-pending-adapter` with `userDecisionRequired` (fail-closed, capability-gap documented) instead of inventing a mechanism or secret. Native YOLO keeps native search with no added clamp (D6).
- Update 14a/14b seam data **additively**: the web-search inventory row gains a `completing-adapter` marker naming this change and the search route table where a supported backend + transport contract is satisfied (backend present under the credential set), while the public-code-search row and every no-backend/credential-absent case keep the distinct pending-adapter outcome; 14b's composition distinguishes completed from pending unchanged, no table shape or error vocabulary revisited.
- Add the trusted-extension `web_search` sibling in the row-12/13/14b/17 tree (the fifth serial extension before row 20's digest cut): register a `web_search` name replacement via the pinned `registerTool` surface (`extensibility/extensions/types.ts`) with S8 native capture; the restricted branch serves the audit-selected supported backend entirely through the adapter (never native provider `fetchWithRetry` global fetch), delegating any non-search-tool input and the YOLO branch to the captured native via `ctx.invokeTool`. 14b still gates every call first; the replacement adds no second decision path.
- Acceptance is deterministic unit/mock ONLY: mocked provider endpoints/DNS/redirect chains assert allow/deny/routing/credential-scope decisions, error-shape honesty (auth vs rate vs empty vs transport), citation/interface stability against the native `formatForLLM` layout, unrestricted-egress pass-through posture, and the blocked-route fail-closed path when no supported backend/credential exists. **Nothing contacts the network, no paid/live search.** Tests certify adapter decisions only; the actual native search tool using the adapter stays on the design section-15 user checklist and cannot be claimed from mocks (per P0 fixture rule).
- Explicit non-goals (owned elsewhere, named): URL fetch (row 17, landed, reused read-only — this change is NOT URL fetch), public code/docs search (row 19 `adapt-omp-public-code-search`), search-provider CONFIG UI (none — no new config surface), unrelated vendor-key support (explicitly excluded by design §9), model-routing/role-chain config changes (rows 6/8 own model config), MCP facade (none, design §1/§4), packaging (row 20), OpenCode's existing `websearch` behavior (unchanged), native binary builds and live verification.
- No new `config.yaml`, `.env`, or Helm field expected: the adapter consumes the existing `GEMINI_API_KEY`/`OPENROUTER_API_KEY` (row 7's credential set) and the existing `agent.sandbox.egressProxy`/`egressProxyPort`/`unrestrictedEgress`/`egressAllowHosts` (row 17's posture inputs). If implementation surfaces any new field, this change synchronizes `config.example.yaml`, `.env.example`, and `helm/values.yaml` itself.
