## Goals / Non-Goals

**Goals:** Live web-search parity for restricted OMP through the supported configured credentials only; one pure decision module that delegates every transport decision to row 17's core (no second SSRF/proxy stack); a machine-readable search route table with `supported / candidate-to-verify / no-supported-mechanism` backend tiering and per-route honest verdicts; native-shape results/citations/errors so prompt behavior matches OpenCode parity; additive completion of 14a's web-search seam row ONLY where a supported backend + transport contract is satisfied; deterministic mock-only certification; honest credential-absent fail-closed gap.

**Non-Goals:** No URL-fetch/URL-read work (row 17, landed — its completed set is untouched), no public code/docs search (row 19), no search-provider CONFIG UI or arbitrary-provider config (none, ever), no unrelated vendor secret (`BRAVE_API_KEY`, `TAVILY_API_KEY`, `EXA_API_KEY`, … — explicitly excluded by design §9), no model-routing/role-chain configuration changes (rows 6/8 own model config; this change SELECTS only among already-supported backends), no MCP facade, no packaging (row 20), no OpenCode behavior change, no YOLO clamp (D6), no live/paid search or native binary runs, no new config/env/Helm fields, no modification of `ssrf.ts`, `egress-proxy.ts`, `fetch-transport.ts`, `fetch-routes.ts`, or 14b's composition table.

## Decisions

### D1. Backend tiering is frozen source data, credential-set-keyed

The tiering (proposal bullet 1) is implementation data in `src/acp/omp/search-routes.ts`, keyed to row 7's exact credential set: Gemini-grounding and OpenRouter-grounding are **supported** (W4/W5: endpoints, credential resolution, availability checks all reachable from the two supported env keys through the native `AuthStorage` cascade — no new field). Grounded `anthropic`/`codex`/`xai`/`openai` and the paid `web/<id>` engines are **no-supported-mechanism-under-this-credential-set**: they exist in the pinned catalog (W3) but each requires a credential outside the set, and design §9 plus the batch out-of-scope list refuse to add one "merely to select OMP". The keyless scraping engines (`duckduckgo`, `mojeek`, `ecosia`, `startpage`, `public`, scraping `google`) are **candidate-to-verify** and explicitly NOT selected: admitting a scraping backend would be operator-unconfigured arbitrary-provider behavior, which the batch forbids. Tests assert the tiering data, never network behavior.

### D2. `registerTool` name replacement of `web_search`; row-17 decision core does every transport decision

The trusted-extension tree gains a `web_search` replacement sibling (fifth serial extension of the 12→13→14b→17 tree). Restricted branch: validate the call input against the native `webSearchSchema` shape (query interface parity), select ONLY the supported backend whose credential the process actually has (decision inputs: which of `GEMINI_API_KEY`/`OPENROUTER_API_KEY` are present in the process env as passed by row 7 — a decision input, never logged), construct the provider request natively (Gemini developer endpoint + `x-goog-api-key` header, or OpenRouter `${baseUrl}/chat/completions` + web plugin), and issue it via `executeSearchRoute(request, deps)` where `deps.decideHop = decideFetchHop`-equivalent from `src/acp/omp/fetch-transport.ts` (W6's `params.fetch` seam is exactly why a replacement, not injection, is selected: nothing on the ACP path populates it, mirroring row 17's D2/S9 reasoning). Every hop — endpoint request AND enrichment subrequests — gets the row-17 treatment: validating-proxy routing under enforcing posture (`getRunningEgressProxyUrl()`), manual per-hop redirect revalidation through `ssrf.ts` rules, `MAX_REDIRECT_HOPS = 5`. The provider's own `fetchWithRetry` backoff is NOT reused on the restricted path: retries outside the controlled transport would be the unguarded native retry design §9 forbids; the adapter's error honesty rule is "provider failure = honest tool error", so the replacement issues ONE controlled attempt per decision and surfaces failure verbatim-classified. YOLO and any non-restricted shape delegate to the captured native via `ctx.invokeTool` (W10), unclamped (D6). `src/acp/omp/search-transport.ts` is the pure core: `decideSearchRoute(input, deps)` (endpoint/enrichment URL → row-17 decision + credential-scope verdict) and the native-shape result mapping from D3.

### D3. Interface parity is the contract, not an impression

The replacement's output MUST be byte-shape-comparable to native: same `{content:[{type:"text"}], details.response}` envelope (W8), `formatForLLM`-layout text (Sources/Citations sections with title/url/snippet attribution), same empty-vs-error distinction — zero-available-credential case yields the native-shaped `Error: No web search model configured.`-family message via the fail-closed path of D4, provider auth/rate/HTTP failures yield honest `Error: <provider>: <classified message>` tool errors matching `formatSearchProviderFailure` shape, and a zero-source success yields the native 204-style honest failure, never an answer-shaped fabrication. The replacement re-implements ONLY formatting/decision; provider response parsing mirrors the pinned parsers' observable fields (answer/sources/citations). Query params pass through 1:1 (W2 field names); the model-role chain is NOT re-implemented — selection is backend-presence per D1, and an explicit `model` param outside the supported set is an honest error, not a silently widened route.

### D4. Credential-absent path stays blocked with `userDecisionRequired`

If neither supported backend's credential exists for the restricted process, there is NO adapter completion: the seam reports `blocked_pending_adapter`-style fail-closed with the capability gap documented (`docs/OMP_NETWORK.md` search section), 14b keeps blocking the call, and the user decision — add a supported provider credential via row 7's approved config path, or accept the parity gap — stays user-owned. The replacement never reaches the network in this state; no scraping fallback, no invented mechanism.

### D5. Enrichment subrequests are model-route decisions with a provider-host allow-shape

Grounding-redirect HEADs (W7) are secondaries of the provider response, not model-supplied URLs: they enter the same row-17 decision as secondary hops (public-only, per-hop validation, 5-hop bound, manual redirect). The decision core adds no allowlist; the enrichment URL's host comes from the provider payload, so SSRF rules apply unchanged — a hostile/odd `Location` to a private space blocks exactly like row 17's public→private redirect case. Enrichment failure keeps the proxy URL natively (silent-but-honest native behavior); blocked enrichment is recorded with `{ host, hopIndex, decision, reason }` credential-free records (row-17 D6 posture reused verbatim, including no-credentials-in-logs: the Gemini path redacts the API key from error text natively; the adapter keeps that redaction).

### D6. Trusted provider endpoints vs model fetch targets — unchanged separation, extended input class

Row 17's D5 separation holds: Skill API loopback and the proxy endpoint stay out of every decision. The search adapter adds ONE consumer distinction the fetch adapter never had: operator-configured provider endpoint hosts (Gemini/OpenRouter bases from the pinned catalog/owned settings of row 8) are still validated like every target — the adapter never exempts them from `ssrf.ts` rules or issues them direct under enforcing posture; they are public provider hosts by fact, and the enforcing posture routes them through the validating proxy. Provider CREDENTIALS appear only in request construction (header from `AuthStorage`/env resolution at request time) and never in decision records, route-table data, logs, or test fixtures.

### D7. Route-table addition is row-scoped and additive

`src/acp/omp/search-routes.ts` rows: `web_search.grounding.gemini` (`completed-by-adapter` when credential present, citations W4/W6/W7, mechanism = D2 replacement), `web_search.grounding.openrouter` (`completed-by-adapter` when credential present, W5/W6), `web_search.grounding.grounding-redirect-enrichment` (`completed-by-adapter` as a secondary-hop route of the completed backends, W7), `web_search.unsupported-credential-set.backends` (`no-supported-mechanism`, `userDecisionRequired`), `web_search.scraping-engines` (`candidate-to-verify — not selected`, `userDecisionRequired`), `web_search.native.global-fetch-provider-path` (`blocked-pending-adapter` for any caller outside the replacement, W6, mirrors row 17's native-function rows). 14a's web-search inventory row gains the additive `completing-adapter` marker naming this change + this table — the marker is backend-gated (it completes only where D1/D2 hold; credential-absent deployments still see the pending outcome per D4), and the public-code-search row stays byte-identical pending. Row 17's `fetch-routes.ts` `search-provider.subrequests` row is NOT edited here: consumers resolve it through this table's completion marker (row 17's registry stays stable as its contract says); a route-table test pins the two tables' agreement so the old pending row can never be cited while this adapter claims completion.

### D8. Test surface is decisions, not plumbing; P0 fixture rule holds

`tests/acp/omp-search-transport-decisions.test.ts` (mocked transport/DNS): Gemini- and OpenRouter-endpoint public HTTPS targets allowed — enforcing names the proxy route, unrestricted routes directly with no new denial (D6-posture parity); loopback/RFC1918/link-local/ULA/metadata endpoint or enrichment-redirect targets blocked with class named; a synthetic grounding-redirect `Location` to private blocks at the hop; >5-hop provider redirect blocks with the hop-limit reason; credential-scope: fixtures with both keys / one key / neither key produce backend-selection / second-backend / D4-fail-closed decisions with NO network call in the third case; `NO_PROXY`-style bypass fixtures assert a model-derived (enrichment) private target NEVER reaches the direct path. `tests/acp/omp-search-interface-shape.test.ts`: mocked provider responses (answer+sources, citations-only, empty-sources 204, 401 auth, 429 rate, malformed JSON) assert the D3 envelope/layout/error-shape stability field-by-field, empty-vs-error discrimination, and a records scan proving no credential/header/query material escapes. Route-table suite: tiering data, marker ≠ allow, credential-absent keeps pending, 14a additive delta doesn't break its own pending-vs-allow test, and the cross-table agreement with row 17's registry. Positive replacement-mechanism fixtures are labeled synthetic per the P0 fixture rule; zero live/paid search anywhere; native-usage claims stay section-15 user-owned.

## Risks / Trade-offs

- **The `web_search` replacement could prove unusable in the compiled binary** (W10 is static) → it is the same mechanism row 17 selected (registerTool + native capture); if section-15 observation disproves it, both URL-read and search escalate together via the P0-revision + user-decision path with `rejected_pending_adapter` standing meanwhile — fail-closed, exactly the design's escalation, not a silent cut.
- **Adapter re-implementation of provider request/parsing could drift from native behavior** (Gemini SSE stream parsing, OpenRouter annotation shapes) → the replacement covers only the two supported backends, mirrors the pinned parsers' observable fields, and pins output shape with fixture comparisons against fixtures generated from the pinned parsers' field contracts; drift surfaces as a failing shape test, and worst case the route honestly reports provider-shaped errors — never fabricated results. Residual enrichment-stream complexity is enumerated in the route table, not assumed away.
- **Gemini `webSearchModel`/hosted-placeholder semantics differ between native chain and adapter selection** → D3 deliberately does not re-implement the role chain; hosted-model expansion is not part of the supported set (it depends on the session chat model's grounding, i.e. arbitrary other providers) — documented as a scope fact: parity is live search through supported credentials, not every native chain behavior; the gap is honest, listed in docs, and section-15 user-checklist-adjacent.
- **A credential present but invalid/quota-exhausted** → honest provider error per D3 (401/429 classified messages), no fabricated fallback, no automatic switch to the other backend unless its credential independently passes availability — matching native candidate-loop semantics on the two-candidate set.
- **Serial-tree collision risk** → this is the 5th serial extension before row 20; the proposal's conflict table names the exact order; the seam edit is one additive marker; `fetch-transport.ts`/`fetch-routes.ts` imports pin behavior with a divergence test (adapter never allows what row 17's core blocks).
- **Unrestricted-posture deployments could perceive the adapter as new denials** → same posture-preservation tests as row 17 (only the shared `ssrf.ts` rule set appears), and YOLO never sees the replacement (D6 design posture).

## Migration Plan

Additive: pure modules + one extension-tree sibling + marker data land behind the existing restricted launch path (restricted sessions only; native YOLO registers no replacement, per 14b posture). Rollback = remove the sibling's attach; `web_search` reverts to 14b's `rejected_pending_adapter` block — never to unadapted native provider transport — fail-closed by construction. No config, state, or data migrations; OpenCode flows untouched.
