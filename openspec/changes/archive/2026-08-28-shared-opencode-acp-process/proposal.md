# Proposal: Shared OpenCode ACP Process Pool with JWT Skill Authentication

## Why

Every conversation currently spawns a fresh `opencode acp` subprocess (one per session across all six `SessionOrchestrator` process paths), so the agent cold-start cost (process launch, config/provider/model loading, MCP startup) is paid on every single conversation. In shared-process mode the per-spawn env-var injection (F12 per-session `XDG_DATA_HOME`, F13 per-session `SKILL_API_TOKEN`) stops working because the process environment is fixed at spawn, so the Skill API authentication must be redesigned as a self-contained, server-verifiable signed token. This change eliminates the per-conversation cold start and introduces JWT-style signed authentication for the Skill API.

## What Changes

- **NEW** Per-channel shared `opencode acp` process pool, keyed by canonical pool keys: message/channel-lurk sessions use `{platform}:{channelId}`; spontaneous sessions use the scheduler's target channel; self-research uses `self-research:{userId}` and memory-maintenance uses `memory-maintenance:{workspaceKey}` (each non-message session type gets its own dedicated process). Multiple ACP sessions run on the same stdio connection (OpenCode supports cross-session parallelism and `session/load` resumption — verified against the OpenCode source). The process is launched lazily on the key's first session and reclaimed when no leased session (queued, in-flight, or recovering) remains after `reclaimIdleMs`.
- **NEW** Global serialization of agent sessions: exactly one agent session holds the execution lease at a time (single-bot-persona semantics); the lease covers the FULL agent lifecycle (session creation, config calls, prompt/retry, cancel/recovery, cleanup). User-triggered sessions take queue priority over maintenance jobs. This keeps the shared `active.json` pointer unambiguous — it is written atomically only while the session holds the lease.
- **NEW** Per-session JWT for the Skill API: a standard 3-segment JWT (`{"alg":"HS256"}`) per session, payload `{ sub: <owning sessionId>, channel: <session channelId>, jti: <per-session callerToken>, iat, exp }`, signed with the deployment-level `SKILL_API_SECRET`, issued (or re-issued with a fresh `exp`) when the session ACQUIRES the execution lease (not at registration, so queued sessions never present an expired JWT); written atomically (temp file + rename, `0600`) and deleted at session end. The server verifies four checks: (1) HMAC-SHA256 signature, (2) `sub == request sessionId`, (3) `channel == session channelId`, (4) `jti == session callerToken` and `exp` not passed.
- **BREAKING** F13 raw Bearer `callerToken` authentication is removed (project is pre-release, 0 users — no backward compatibility required). The skill lib presents the per-session JWT instead; the owning session ID is resolved from the `SESSION_ID` env var in per-spawn mode, or from the orchestrator-maintained `{SKILL_JWT_DIR}/active.json` pointer in shared mode (written atomically only while the session holds the execution lease, and snapshotted by the skill script at script start).
- **CHANGED** `XDG_DATA_HOME` (F12) becomes channel-scoped: the shared process uses `{dataRoot}/opencode-data/{poolKey}` and `TMPDIR` uses `{dataRoot}/channel-tmp/{poolKey}` — channel/pool-key-scoped data roots under the bot data root, deliberately OUTSIDE any user's per-user workspace (avoids cross-user visibility); the permission gate's tool-output boundary follows the channel-scoped data root.
- **CHANGED** Doom-loop termination in shared mode issues ACP `session/cancel` on the current session instead of killing the shared process.
- **NEW** Session resumption with controlled recovery: on idle timeout / process death, the channel process is restarted and the in-flight session is resumed via ACP `session/load`; the prompt is re-issued ONLY if no response (reply/reaction/file) was sent yet — no duplicate replies or memory events.
- **NEW** Deployment-level `SKILL_API_SECRET` (256-bit CSPRNG) generated at bootstrap and persisted to `data/skill-secret` (env-overridable); held ONLY by the bot process (JWT issuer + Skill API verifier). The agent process receives the per-session JWT file via `SKILL_JWT_DIR` (a minimal session capability), never the raw HMAC key.

## Capabilities

### New Capabilities

- `shared-acp-process-pool`: long-lived `opencode acp` process pool with canonical pool keys (`{platform}:{channelId}` for message/lurk, target channel for spontaneous, `self-research:{userId}`, `memory-maintenance:{workspaceKey}`) — lazy spawn, multiple ACP sessions per stdio connection, reference-counted reclaim, global execution-lease serialization (full agent lifecycle, interactive-before-maintenance queue priority), and controlled session resumption via `session/load` (re-prompt only when no response sent).
- `jwt-skill-auth`: per-session signed JWT authentication for the Skill API — JWT issued/re-issued at execution-lease acquisition (atomic write, deleted at session end), skill-lib presentation via `SESSION_ID` env var (per-spawn) or the lease-written `active.json` pointer (shared), snapshot at script start, and the server-side four-check verification (signature, `sub`, `channel`, `jti` + `exp`).

### Modified Capabilities

- `acp-integration`: The "AgentConnector Subprocess Management" requirement changes — from per-session spawn/connect/disconnect to a shared process mode (connect once per pool key, `newSession` per conversation, controlled reconnect + `session/load` resumption on idle timeout / process death). Adds a session-scoped connector state requirement: the connector's mutable state (`configOptions` cache, current model ID, idle monitor) is indexed by ACP session ID, and the execution lease covers the full agent lifecycle.
- `skills-and-reply`: The "Session-Based Authentication" requirement changes from raw per-session `callerToken` Bearer auth to per-session signed JWT (BREAKING); "Shell-Based Skill Execution" changes how the skill script obtains the owning session ID (env var vs. `active.json` pointer, snapshot at script start); "Reply Rules" doom-loop termination changes from process kill to ACP `session/cancel` in shared mode.
- `agent-sandbox-hardening`: The "Per-Session Tool-Output Isolation" requirement changes from per-session `XDG_DATA_HOME` to a channel/pool-key-scoped data root under the bot data root (outside any user's workspace); the sandbox env-var allowlist gains `SKILL_JWT_DIR` pass-through (the `SKILL_API_SECRET` stays in the bot process only).

## Impact

- **Code**: `src/acp/agent-connector.ts` (shared-process mode, controlled `loadSession` recovery, `session/cancel`; mutable state — `configOptions` cache, current model ID — indexed by ACP session ID), `src/core/session-orchestrator.ts` (process pool with canonical pool keys, global execution-lease serialization with queue priority, per-session JWT issued at lease acquisition, lease-written `active.json` pointer), `src/core/agent-core.ts` (bootstrap the pool + secret), `src/skill-api/server.ts` (JWT verification), `src/skill-api/session-registry.ts` (`callerToken` retained as the JWT `jti`), `skills/lib/client.ts` (JWT presentation, owning-session resolution + snapshot at script start), `src/acp/agent-factory.ts` (env var changes: add `SKILL_JWT_DIR`, remove `SKILL_API_TOKEN`; `SKILL_API_SECRET` is NOT passed to the agent process), `src/acp/sandbox-manager.ts` (env allowlist), `src/bootstrap.ts` (secret generation + persistence, bot-process only).
- **Config**: new `agent.sharedProcess` block (`enabled`, `reclaimIdleMs`, serialization mode); synced to `config.example.yaml`, `.env.example`, `helm/values.yaml` (CI checklist requirement).
- **Behavior**: conversations in the same or different channels are serialized globally (one agent session at a time); the Skill API now requires a signed JWT in the `Authorization` header.
- **Tests**: new unit tests for the process pool, serialization queue, JWT issuance/verification (all four checks + failure paths), skill lib resolution; existing tests updated. CI: `deno fmt`, `deno lint`, `deno check`, `deno test`, coverage ≥ 75%.
