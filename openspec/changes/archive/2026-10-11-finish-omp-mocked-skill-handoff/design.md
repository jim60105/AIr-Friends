## Decisions

### D1. Three-tier harness composition, reused not forked

| Tier | Drives | Used for |
| --- | --- | --- |
| Full-stack | real `SessionOrchestrator` + real `AgentConnector` + real `SkillAPIServer`/`SessionRegistry`/handlers + extended `mock-acp-agent.ts` subprocess + `MockPlatformAdapter` | every handoff/retry/quota/summary-gate scenario (the §14 reply-flow row demands real handler logic end to end) |
| Connection-tier (row 21's `mock-acp-connection.ts`) | real connector/orchestrator with scripted in-process ACP | auth/containment-failure composition where subprocess skill spawning adds no evidence |
| Direct-call | real `SkillAPIServer` request with fabricated callers | negative auth/containment vectors only (already row-21-style; never restating tests/skill-api units) |

All fixture composition routes through `omp-mock-session.ts` (additive fields only, e.g. `{ skillCall?: { skill, args, payloadFile } }` observation scripting on the mock agent). No scenario hand-rolls fixture plumbing; no scenario duplicates row 16's task-4.3 component chain or any `tests/skills/*`/`tests/skill-api/*` unit assertion — the delivery scenarios' distinguishing observable is the orchestrator-level outcome (registry state, retry count, platform-call ledger, summary invocation), not handler internals.

### D2. Ephemeral-port Skill API + per-test JWT dir; the seam policy made concrete

The suite starts `SkillAPIServer` on port 0 (ephemeral) per test file, reads the bound port, and passes `SKILL_API_PORT`/`SKILL_JWT_DIR` through the SAME env-assembly path production uses (row 7's filtered base set already passes `SKILL_API_PORT`; `SKILL_JWT_DIR` is the existing skill-client env input). If the orchestrator's spawn path offers no way to point the mock ACP subprocess at the ephemeral port/JWT dir without touching `src/**`, the pre-declared single test-only seam applies: one additive, default-preserving injection point on the spawn-env assembly (identical shape to row 21's launch-override precedent), flagged in the return. Expected unnecessary — the connector spawns whatever command/env the factory composes, and the existing OpenCode shared-process suite already controls this surface from tests.

### D3. Mock-agent skill invocation executes the REAL scripts

The extended `mock-acp-agent.ts` gains one scripted behavior: on a prompt whose staged instructions name a skill call (fixture-carried, not parsed prose), the mock spawns the real `skills/{name}/scripts/{name}.ts` via `deno run` with the fixture's literal argv (`--session-id <literal>` + absolute payload/`--file-paths` flags) against the ephemeral Skill API, then reports `end_turn` — optionally after writing the payload file itself at the absolute staging path via the mock's own fs access (standing in for "the agent wrote the file"; the WRITE-AUTHORIZATION decision under test is row 4's client-side sink gate, exercised in the auth/containment scenario, not simulated). This keeps the JWT, containment, registry-state, quota, and reply-handler logic all real, matching §14's "use actual handler code" rule; the OpenCode mock behavior stays byte-compatible (the new behavior triggers only on the new scripted marker).

## Risks / Trade-offs

- **Real subprocess + real HTTP server = flakiness risk** → only two scenario families spawn skill scripts through the mock subprocess; completion is event-signaled (D6), ports ephemeral, JWT dirs per-test; the connection-tier covers failure vectors without subprocesses.
- **Scope creep temptation from eight docs files** → append-only cross-links plus the explicitly authorized register/index decision synchronization, one new checklist artifact and the owned prose files; any discovered content drift in `docs/OMP_*` is recorded in the audit table, not silently rewritten (rewriting another row's honest verdict text is a review blocker).
- **Audit finds real trio drift** → handled by design: docs-only fix in this change, entry recorded in CHANGELOG; no behavior change, no field invention.
- **Parallel-run port collision with existing suites** → ephemeral ports + per-test dirs (D2); the new suite never binds 3001.
- **Row 21 builder needs a field row 22 forgot** → the contract makes additive extension legal only here; if the builder shape is genuinely insufficient, extension stays additive with existing lifecycle behavior unchanged (existing builder unit assertions must stay green).
