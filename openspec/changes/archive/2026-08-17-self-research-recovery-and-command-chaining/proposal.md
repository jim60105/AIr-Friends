## Why

A production self-research session (export-8defc0ea1d331b2.clef, 2026-08-16) failed its job and the harness reported it as a success. The agent's research flow was blocked twice by the restricted-mode permission gate — `cat <index> 2>/dev/null || echo "NO INDEX"` (rejected: `>` file redirect + `||` + `echo`) and `agent-browser open <url> 2>&1; agent-browser get text 2>&1` (rejected: `;` chaining) — and then it surrendered with `end_turn` after ~38s and 36K/1M tokens without writing any note. `processSelfResearch` declares `stopReason === "end_turn"` a success and has no completion verification, no retry, and no observability, so the scheduled research silently produced nothing. This is the third occurrence of the same failure class (the 2026-08-14 `2>&1` tolerance change fixed the trailing-redirect instance of the model's bash batching habit; the `;`/`||`/`&&` chaining and fallback-redirect instances remain), and prompt guidance actively misleads the agent (`agent_permissions.md` claims `curl` is allowed although the gate and `opencode.json` deny it; nothing documents the chaining rules).

## What Changes

- **Segment-aware approval of multi-command bash invocations in the ACP permission gate**: a single bash tool call containing multiple commands separated by `;`, `&&`, or `||` SHALL be approved iff EVERY segment independently passes the exact same gate it would face as its own tool call (skill whitelist matcher OR generic-command allowlist with first-token, dangerous-flag, and path-containment checks; tolerated `N>&[12]` fd-redirect tokens continue to apply per segment). Splitting SHALL be quote-aware (outside `'`/`"` only) and conservative (unbalanced quotes → single segment; empty segments skipped; a segment containing ONLY fd-redirect tokens is rejected as an operator artifact; a chain with any failing segment is rejected with the FIRST failing segment's cause). Pipes `|`, backgrounding `&`, newlines, and all other shell operators remain rejected. This is not a capability grant — every segment could already be run as its own gated tool call — it removes the forced single-command round trips that cause models to batch and, as observed, to surrender.
- **Shell-expansion token tightening (prerequisite for the chaining rule)**: the per-token path checks in the gate expand ONLY the harness-set variables (`$HOME`, `$XDG_DATA_HOME`, `$TMPDIR`, `$AGENT_WORKSPACE`, `$SESSION_ID`) and reject every other unquoted `$VAR` reference and unquoted brace-expansion token (`{...}`) — closing a pre-existing hole where `cat $IFS/etc/passwd` or `cat {safe,/etc/passwd}` could make an in-workspace-looking token expand to an out-of-workspace path at runtime. Without this, the "every segment is individually safe" basis of the chaining rule would be unsound.
- **Self-research completion verification + corrective retry**: after `end_turn`, `processSelfResearch` SHALL verify that the agent actually produced research output (a new file, or a content-changed file whose mtime is within the session window, under `$AGENT_WORKSPACE/notes/` or `journal/`). If none: the session SHALL be recorded as a FAILURE (audit `session_end` with `success: false` and reason, WARN log, dedicated Prometheus counter), and the harness SHALL send ONE corrective retry prompt on the same ACP session that names the sandbox rules that blocked the agent (reusing the existing per-session permission-rejection ring buffer via `formatPermissionRejections`, plus the commands OpenCode itself denies before the ACP gate) and instructs it to complete the note. If the retry still produces nothing, the session ends as a failure. The retry prompt and response SHALL be recorded in the audit log, and exactly ONE `session_end` entry SHALL be written after the final outcome. **BREAKING** (semantics only): a self-research session that produces no note is no longer reported as successful.
- **Prompt/skill guidance aligned with the real gate**: fix the false `curl` claim in `prompts/agent_permissions.md`; document in `prompts/browser_automation.md` that multi-command bash calls are allowed with `;`, `&&`, or `||` only when every command is individually allowed, that `|`, `&`, `2>/dev/null`, `> file`, `|| echo`-style fallbacks are rejected (and `echo`/`curl`/`git` are denied by OpenCode before the ACP gate), and that webfetch 403/429 responses should trigger an immediate switch to `agent-browser`; update `skills/self-research/SKILL.md` to use the Read tool for the notes index via `$AGENT_WORKSPACE` (deployment-independent path) and to mention the sandbox command rules.
- **Config + metrics**: add `selfResearch.verifyCompletion` (default `true`) with `SELF_RESEARCH_VERIFY_COMPLETION` env override; add a `airfriends_self_research_no_note_total` counter that increments only when completion verification is enabled and a session ends without a note. Document both per project convention (`config.example.yaml`, `.env.example`, `helm/values.yaml`, `docs/AGENT_PERMISSIONS.md`).

## Capabilities

### New Capabilities

- *(none — this change modifies existing capabilities only)*

### Modified Capabilities

- `agent-sandbox-hardening`: the restricted-mode command gate approves `;`/`&&`/`||`-chained multi-command bash invocations when every segment independently passes the existing single-command gate; per-token path checks reject unexpanded non-harness `$VAR` references and brace-expansion tokens; all other shell operators stay rejected.
- `self-research`: sessions must produce a research note to count as successful; otherwise one corrective retry with permission diagnostics runs, and the session is recorded as a failure.
- `metrics-export`: a new `airfriends_self_research_no_note_total` counter is exposed for self-research sessions that ended without producing a note.
- `configuration-and-deployment`: `selfResearch.verifyCompletion` config field and `SELF_RESEARCH_VERIFY_COMPLETION` environment variable override.
