## Context

`AgentConnector` already caches per-ACP-session `configOptions` (`sessionConfigOptions` map), refreshed from the `newSession` response, `set_config_option` responses, and `config_option_update` notifications, and it discovers the `thought_level` option from the latest cache at apply time (`findThoughtLevelOption`, `collectOptionValues` flattens flat options and `SessionConfigSelectGroup` groups). Model selection, however, unconditionally calls `connection.unstable_setSessionModel()` even when the Agent advertises the stable `category: "model"` select option, and reasoning application maps a known token absent from the advertised values to `skipped_unavailable` — so a requested `none` is lost on an agent that advertises only `off`. `reconnectAndResumeSession()` calls `connection.loadSession()` and discards the response, so after recovery the config-options cache is empty and neither the model nor reasoning effort is re-established. ACP SDK 0.14.1 types confirm `NewSessionResponse`, `LoadSessionResponse` and `SetSessionConfigOptionResponse` all carry `configOptions?: Array<SessionConfigOption> | null`, `SessionConfigOptionCategory` includes `"model"`, and option values may be a flat `SessionConfigSelectOption[]` or a `SessionConfigSelectGroup[]` (the pinned OpenCode behavior must not regress: agents that never advertise a `model`-category option must keep today's unstable path byte-for-byte). See proposal.md for motivation.

## Goals / Non-Goals

**Goals:**

- Stable-first canonical model selection: advertised `category: "model"` option wins; grouped catalogs flattened; case-insensitive match; canonical advertised value sent via `session/set_config_option`; `sessionModelIds` records the canonical value sent.
- Catalog miss against an advertised catalog is one explicit error; unstable fallback ONLY when the stable option is absent.
- Cache currency from every source: new/set responses and notifications (existing) plus the `session/load` response.
- Reasoning: exact canonical match preferred; `none`→`off` only when no exact `none` exists; `default` no-op; all outcomes and best-effort/non-fatal treatment preserved.
- Reconnect restores the canonical cache from the load response and reapplies model (stable-first, error propagates) then reasoning (best-effort) through the same logic.
- Pure resolution logic in one small shared module so rows 10/11 and the dashboard consume one convention.

**Non-Goals:**

- No factory, pool-acquisition, mode-resolution or process/state-identity changes (rows 9/10); no original-mode/namespace verification or gate-context/readiness restore wiring (row 11); no orchestrator call-site restructuring (callers keep signatures; the new error flows through their existing per-session failure handling); no agent-type parsing or selector filtering (row 7); no P0 contract edits; no config/env/Helm fields; no SDK upgrade; no live OMP or OpenCode runs; no combined lifecycle regression suite (row 21).

## Decisions

**D1 — Resolution lives in a new pure module `src/acp/session-config.ts`; the connector stays the only RPC owner.**
Functions (all pure over cached option lists): `findOptionByCategory(options, category)`, `collectOptionValues(option)` (move or delegate to the connector's existing flattener — grouped and flat entries, skipping entries lacking a string `value`), `resolveCanonicalValue(available, requested)` (exact case-insensitive first match, returns the advertised casing), `resolveModelSelection(options, requested)` returning one of `{ kind: "stable", configId, value }`, `{ kind: "unstable-fallback" }`, `{ kind: "catalog-miss", available }`, and `resolveReasoningValue(requested, available)` implementing exact-match-then-`none`→`off`. Alternative considered: inline all logic in `agent-connector.ts` — rejected because row 11's load-reconnect consumers and its tests need the same verdicts without a live connection, and a private duplicate of the matching rules is exactly the divergence the design forbids. The module performs no IO and knows nothing about connections, so it remains unit-testable and pool-safe.

**D2 — `setSessionModel` is stable-first with a strict three-way outcome, and remains a throwing API.**
`setSessionModel(sessionId, modelId)` consults `sessionConfigOptions.get(sessionId)` at call time (never a creation-time snapshot). `catalog-miss` throws a descriptive `Error` naming the requested model, the agent type and a bounded list of advertised values (bounded to keep logs sane; full list stays in a structured warning). `stable` calls `setSessionConfigOption({ sessionId, configId, value: canonical })` through `raceAgainstCrash` and refreshes the cache from the response (already the reasoning path's pattern — factor that refresh so both callers share it). `unstable-fallback` invokes today's `unstable_setSessionModel` path unchanged. In all success paths `sessionModelIds.set(sessionId, valueActuallySent)`. Rationale for throwing rather than a soft outcome: design §10 says explicit error, and every existing caller already wraps `setSessionModel` inside per-session error handling (orchestrator per-session try/catch, dashboard request error), so a thrown error is the existing consumer-visible failure idiom; a new return-type union would force edits in nine orchestrator call sites, exceeding the budget while touching rows 10/11's territory. Alternative considered: return an outcome object like reasoning — rejected for blast radius; the `acp-integration` spec's "configure via the ACP connection" requirement plus caller try/catch make throwing equivalent and non-breaking for the pool's crash-recovery error matching (which keys on the crash error class, not message text).

**D3 — One canonical value rule; `model`-category discovery mirrors `thought_level` discovery.**
The stable model option is located by `category === "model"` on the session's latest cached options, exactly like `findThoughtLevelOption`. Case-insensitive matching with advertised-casing egress is already the proven convention for reasoning; reuse it for models so agents owning their ID casing (OpenCode-style, OMP catalogs) receive their own bytes. Ties (two values differing only by case) resolve to the first advertised, documented in tests. `sessionModelIds` stores the canonical sent value so reasoning-warning context and later diagnostics report what the agent actually holds. Alternative: send the requested casing — rejected: design §10 mandates the canonical advertised value, and provider/model IDs are agent-owned identifiers.

**D4 — Reasoning: exact match first, `none`→`off` as a bounded alias, outcomes untouched.**
In `setReasoningEffort`, after computing `canonicalMatch` as today: if absent and the requested token is `none`, look for advertised `off` (case-insensitive) and use it; if `off` is also absent the existing `skipped_unavailable` branch applies unchanged (passthrough behavior for unknown tokens unchanged). The alias fires only for requested `none` — never for `off`→`none` or any other token — so OpenCode catalogs that advertise `none` keep sending `none`. `default`/empty remains `skipped` before any catalog inspection. Rationale: preserves every existing outcome (`applied`/`unsupported`/`skipped`/`skipped_unavailable`/`failed`) and the non-fatal contract, adding one lookup branch. Alternative: normalize catalogs to our vocabulary — rejected, rewrites agent-owned values.

**D5 — Load-response restoration: connector restores the cache and re-sends the prior model; reasoning is caller-optional.**
`reconnectAndResumeSession(sessionId, cwd, mcpServers, opts?: { reasoningEffort?: string })` (new OPTIONAL trailing parameter; existing call sites compile unchanged): after `loadSession()` resolves, `refreshSessionConfigOptions(sessionId, response.configOptions)` — nullish load response clears to empty exactly like today's refresh contract, so a load that advertises nothing leaves the cache empty and stable-first logic will choose the unstable fallback for the prior model, matching pre-change OpenCode behavior. If `sessionModelIds` holds a prior model, re-run the same stable-first selection: catalog-miss throws (propagates — a session whose model vanished from the catalog fails isolated, per design §13/§10; the caller's existing resume-failure handling treats it as session loss); `stable`/`unstable-fallback` send as in D2 and refresh the cache from the set response. Then, when `opts.reasoningEffort` is provided and active (`AgentConnector.isReasoningEffortActive`), call the unchanged best-effort `setReasoningEffort` (outcome logged, never fatal). Order is fixed model-then-reasoning because advertised `thought_level` values depend on the model, mirroring the per-context reasoning spec. Alternative: return an outcome object and force row 11 to wire reapplication — rejected: row 11 consumes the same connector method, so restoring config inside it keeps one implementation; the optional parameter avoids touching row 10/11's acquisition code at all.

**D6 — Cache refresh from `set_config_option` responses is factored, not redefined.**
Both the new stable-model set and the reasoning set consume `SetSessionConfigOptionResponse.configOptions` through the existing `refreshSessionConfigOptions`; the notification listener and nullish-clear semantics are untouched, satisfying the existing "Session Config Option Update Handling" requirement without modification.

## Risks / Trade-offs

- [A catalog-advertising agent whose advertised value works but whose requested spelling differs] → canonical-casing egress means the agent receives its own ID; the requested spelling only appears in logs/diagnostics, and `sessionModelIds` holds the canonical value.
- [Stable-first surfaces a catalog-miss error today silently absorbed by the unstable API, turning a previously-"working" session into a failure] → intentional per design §10 (never fall back to unstable after a catalog miss); OpenCode default deploys keep the unstable path because current OpenCode does not advertise a `model`-category option; the failure is explicit, bounded-logged and isolated to the session.
- [`config_option_update` races between reading the cache and sending a set request] → harmless: the set targets the option `id`, the response refresh overwrites the cache, and the next call re-discovers from latest state (existing re-discovery contract).
- [Reconnect now throws on a genuine post-load catalog miss where it previously returned `true` optimistically] → by design the session's model is unrecoverable; existing caller paths already handle a failed resume as session loss, and the failure stays isolated to that session (row 11 formalizes same-mode-only reconnect).
- [Shared `agent-connector.ts` edits collide with rows 10/11] → requirement text names ownership boundaries; the batch table orders this change first and rows 10/11 consume `session-config.ts` rather than re-editing the selection logic.
- [Mocked ACP proves client-side decisions only] → honest per batch rule: unit/mock tests exercise real connector/helper code against mock connections; they do not certify native OMP catalog behavior, which P0 evidence governs and user runtime checks own.

## Migration Plan

Additive cutover in one change: add `session-config.ts`, rewire `setSessionModel`/`setReasoningEffort`/`reconnectAndResumeSession`, no config or data migration, no rollout ordering constraint. Rollback = revert the connector commit; OpenCode default behavior is the unchanged unstable path either direction.

None — casing ties, nullish load responses, reasoning ordering and reconnect error behavior are decided above.
