# Design

## Context

Dependency closure is observable in current code. `tool-inventory.ts` imports `ompSettingsForMode()` to build `row8Restricted`; `extension/index.ts` imports and executes `bootstrapDiscoveryGuard()` before factory registration; `native-registration.ts` infers restricted mode from `omp-agent/<mode>/cwd`; the bundler imports `DEPLOYMENT_MODULE_DEPENDENCY_CLOSURE` and embeds a physical deployment declaration. Deleting only settings or changing cwd breaks those retained consumers. This unit replaces their complete runtime/build closure together after the client, lifecycle and recovery predecessors.

## Goals / Non-Goals

Deliver authored native settings, usable native read/search/skills/network, default deny for unmatched restricted tools, native explicit LSP denial and a small official extension callback. Keep shared ACP authorization as the sole command/destructive/filesystem policy. No YAML mirror, origin/epoch/resource ladder, discovery guard, replacement tool, authenticated readiness or module-file trust remains. No OpenCode JSON or launch changes.

## Decisions

### Native schema and registration reachability

Source pin is OMP v18.6.1, commit `2a2c6dcbbb558c0f8145f67f28b3370984f2bf60`. [Approval documentation](https://github.com/can1357/oh-my-pi/blob/2a2c6dcbbb558c0f8145f67f28b3370984f2bf60/docs/approval-mode.md) establishes `tools.approvalMode: write|yolo` and exact-name `tools.approval.<name>: allow|deny|prompt`, honored in both modes. It has no wildcard default deny. [Extension API](https://github.com/can1357/oh-my-pi/blob/2a2c6dcbbb558c0f8145f67f28b3370984f2bf60/packages/coding-agent/src/extensibility/extensions/types.ts) establishes synchronous `api.on('tool_call', handler)` with `event.toolName` and `{block:true,reason}`. The factory return does not register anything. No `getAllTools`, `registerTool`, trusted session acquisition or schema-builder facade is needed by the replacement.

Restricted launch alone passes `--trusted-extension <bundle>`. YOLO omits it and uses native YAML with explicit `lsp: deny`. The restricted factory always attaches the name-capability handler; it has no cwd/mode observer. This makes mode selection the launch caller's responsibility without an invented environment key or control channel. Native ambient exploration remains enabled by dropping `--no-extensions`; extension flags are not advertised as custom-tool/plugin exclusion.

Native mounted-device reachability is also source-resolved. [SDK registry composition](https://github.com/can1357/oh-my-pi/blob/2a2c6dcbbb558c0f8145f67f28b3370984f2bf60/packages/coding-agent/src/sdk.ts) wraps every canonical registry tool in `ExtensionToolWrapper` before `createXdevState()` receives that same registry. [Native Xdev dispatch](https://github.com/can1357/oh-my-pi/blob/2a2c6dcbbb558c0f8145f67f28b3370984f2bf60/packages/coding-agent/src/tools/xdev.ts) resolves and executes those canonical wrapped tools after native argument validation. Thus `write xd://<tool>` reaches the inner tool's `tool_call` name decision as well as the outer write; no parallel URI authorization engine is required. Native `todo`, `grep` and `web_search` stay top-level through `XDEV_KEEP_TOP_LEVEL`. Acceptance includes a real unknown mounted device as well as direct unknown dispatch.

### Capability mapping and native policy

Replace the old inventory whole-file with a small immutable map, and retain the existing file path to avoid another convention. Exact permitted names map to equivalent OpenCode abilities: `read` (local/URL/skill instruction read), `grep`, `glob`, `find` (local search), `todo` (todoread/todowrite), `web_search` (websearch), `bash` (execute), `edit` and `write` (modify), `delete` and `move` (destructive modify where registered natively/custom). Native `find` stays conditional on its native judge configuration; no new judge provider is introduced. No separate `skill` tool is fabricated; OMP's native skill discovery and `read skill://...` supply that capability. All other restricted names return `{block:true,reason:'rejected_unknown_tool'}`. No source tuple or registry generation affects this decision. Known names continue without re-running native/ACP permission policy. Restricting `lsp` is expressed by YAML and the absent capability mapping; explicit YOLO `lsp` deny remains YAML-only.

Both mode documents remain hand-written. Restricted uses `tools.approvalMode: write` and exact allow entries for `read`, `grep`, `glob`, `find`, `todo`, `web_search`; `lsp: deny` is included. Native `bash`/destructive ACP gates stay in force under non-YOLO. Ordinary native writes use the advertised ACP writeTextFile capability. YOLO uses `approvalMode: yolo` with the single explicit `lsp: deny` exception. Remove `lsp.enabled: false`, `fetch.enabled: false`, all `disabledProviders`, and disabled alternate-skill-source toggles. Keep native `skills.enabled`, supported local-search activation values and current update/compaction settings; this unit does not redesign those independent settings.

Each YAML explicitly authors `skills.customDirectories: ['~/.agents/skills']` for the stock image. Native `expandTilde()` supports this spelling. Development/custom deployments manually author their actual root in both mode files and configure `agent.skillsDir` to the same root. No `${AGENT_SKILLS_DIR}` interpolation, config root consistency rejection, template, startup overlay write or OpenCode JSON translation exists.

### Model file discovery and mutable native data

Current `models.yml` is tracked and packaged but never consumed by the old factory. [Native main](https://github.com/can1357/oh-my-pi/blob/2a2c6dcbbb558c0f8145f67f28b3370984f2bf60/packages/coding-agent/src/main.ts) constructs `new ModelRegistry(authStorage, undefined, ...)`; [model registry](https://github.com/can1357/oh-my-pi/blob/2a2c6dcbbb558c0f8145f67f28b3370984f2bf60/packages/coding-agent/src/config/model-registry.ts) reads `getAgentDir()/models.yml`. `--models` is a model selector scope, not a model-config-file path. Do not invent `--models-config` or pass models.yml as a settings overlay.

[Native dirs](https://github.com/can1357/oh-my-pi/blob/2a2c6dcbbb558c0f8145f67f28b3370984f2bf60/packages/utils/src/dirs.ts) keeps default config at inherited HOME `~/.omp/agent`, and on Linux/macOS redirects data to `$XDG_DATA_HOME/omp` when that app directory already exists and the agent directory is default. Use the existing `ompXdgDataHome(baseRoot,mode)` and create its `omp` child before spawn. Remove the application assignment of `PI_CODING_AGENT_DIR` and the isolated HOME. Native agent DB/session lookup then uses the mode-specific XDG data root while models config remains directly read from inherited HOME. Do not validate profile/settings replacement or suppress operator-native configuration; the stock deployment uses the default profile. Native profile/agent-directory overrides follow upstream behavior without a custom namespace gate.

Move the existing Containerfile models COPY, verbatim, to `/home/deno/.omp/agent/models.yml` in this core cutover so both modes consume the authored provider header immediately. Remove its obsolete `/opt/air/omp/config/models.yml` install. Development deployment instructions provision the same authored file at the operator's native HOME path before launch. Runtime never creates/copies/symlinks YAML. Keep the current models content with OpenRouter `headers.X-Title`; preserve native Gemini/OpenRouter credentials and document the native non-overridable identity headers as source evidence.

Process cwd becomes the existing caller workingDir, including pooled user/session cwd handling. Process TMPDIR uses the existing `channel-tmp/<poolKey>` or per-spawn `workingDir/tmp` convention; session payload staging remains `session cwd/tmp/<Skill API ID>`. Only native XDG data remains mode-specific. Keep OMP pool mode keys, shared marker, JWT dir, active-session pointer, AGENT_WORKSPACE and current proxy behavior. Ordinary sandbox allowlisting still applies. Remove mandatory OMP discovery sanitization and foreign-provider selector blacklists; do not change OpenCode's existing deny entries. Assign the application's chosen XDG data/TMPDIR after existing filtering if necessary, as process data inputs, without reintroducing a settings-source plan.

### Build and deletion closure

Resolve the extension path using the existing generated development `build/omp-extension/index.js` and installed `/opt/air/omp/extension/index.js` constants in `omp-paths.ts`; no deployment evidence selector remains. The required restricted bundle missing-file error retains the existing build-remedy message. YAML parse/validation errors originate from native startup, not app-owned schema mirrors.

Build the replacement entry as one ESM file with frozen lock. Delete declaration embedding/coverage and synthetic input digest headers from `bundle-extension.ts`; remove the assertion that the output contains an inlined `@std` dependency because the small replacement can have none. Keep real native-loadability checks and the output path. Remove `bundle-declaration.ts`. Bundle audit may remain as its genuine build consumer; delete host-facade handling when it has no emitted/source consumer. The image manifest is still consumed by Containerfile until its separately scoped installation change; do not orphan that command in this cutover.

Delete the old runtime closure in `src/acp/omp/`: compatibility ledger/validators, discovery/executable/settings scanners, tool provenance/wiring, approval records/evaluator, destructive adapter, network routes/transports, deployment/owned-module evidence and owned-skills.ts. Delete all old extension files except rewritten `index.ts` and `native-registration.ts`; delete `_daemon/` façade. Keep the new `destructive-ingress.ts` from the predecessor and rewritten capability map. The boundary predecessor removed owned-skills.ts from daemon callbacks but retained it for extension/critical-skills.ts and bootstrap; those last runtime/build consumers disappear in this same core cutover. Remove `src/acp/omp-settings.ts`, `skill-root-declaration.ts` and their obsolete path/type symbols after every importer is migrated. Move the native mode type into `src/acp/types.ts` and update `omp-paths.ts` consumers without aliases.

## Risks / Trade-offs

The coupled architecture would exceed a workday if callback metadata and recovery cleanup were included. Those are complete earlier deliverables; this cutover is consequently a small new handler plus deterministic deletions and launch edits. Estimated 7.75 hours includes 1.50 hours of verification/repair. Each task has a bounded target and no architectural exploration left for the worker. Native extension ordering retains upstream last-registration behavior; no source-based denial or new readiness claim is added. Proxy environment is observed configuration, not proof of network routing.

## Migration Plan

Apply the three predecessors, then land config/launch/extension/bundle/fixture cutover in one implementation change. Rebuild the ESM artifact; build installation may only copy authored YAML. The core updates affected spec removals and launch/tool docs with its code. No migration/shim or unused intermediate module is retained. The later packaging change removes the still-live manifest consumer and permission rules. The final consolidation extends consumer evidence rather than repairing broken imports from this cutover.
